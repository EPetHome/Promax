# 情感分析框架与校准规则

> 应用市场用户评论情感分析标准流程。采用「规则引擎 + 词典匹配 + LLM 语义复核」三段式管线，兼顾准确率与成本。

## 一、四级情感模型

| 等级 | 代码 | 分值 | 说明 | 示例 |
|------|------|------|------|------|
| 正向 | POS | +1 | 满意、推荐、肯定 | 「很好用」「推荐」 |
| 中性 | NEU | 0 | 客观陈述、咨询、无情绪 | 「请问怎么登录」 |
| 负向 | NEG | -1 | 不满、抱怨、失望 | 「越来越难用了」 |
| 愤怒 | ANG | -2 | 强烈不满、辱骂、维权 | 「垃圾！卸载！还钱！」 |

> ANG 是 NEG 的强化形态，仅当评论同时具备**激烈措辞 + 明确指责对象**时才升级。

## 二、关键词词典

### POS 正向词典

| 类别 | 关键词 |
|------|--------|
| 肯定词 | 好用、满意、喜欢、不错、很棒、优秀、给力、良心 |
| 推荐词 | 推荐、强烈推荐、安利、值得下载、比XX强 |
| 感谢词 | 谢谢、感谢、辛苦了、太赞了 |
| 情感词 | 开心、惊喜、爱了、期待更新、越来越好 |

### NEU 中性特征

| 类别 | 关键词 |
|------|--------|
| 咨询词 | 请问、怎么、如何、在哪、吗、？ |
| 陈述词 | 更新了、可以、能用、一般、还行 |
| 场景词 | 今天、昨天、第一次、注册、登录 |

### NEG 负向词典

| 类别 | 关键词 |
|------|--------|
| 功能负面 | 不能用、打不开、失效、没反应、报错、白屏 |
| 性能负面 | 卡、闪退、崩溃、耗电、发热、加载慢、死机 |
| 体验负面 | 难用、麻烦、广告多、弹窗、骚扰、界面丑 |
| 服务负面 | 客服不理、态度差、不处理、踢皮球 |

### ANG 愤怒词典

| 类别 | 关键词 |
|------|--------|
| 辱骂词 | 垃圾、辣鸡、骗子、恶心、什么玩意、卸载 |
| 维权词 | 还钱、退钱、退款、投诉、举报、维权、欺骗 |
| 强调词 | 永远、彻底、再也不用、千万别下载、坑人 |

## 三、否定处理规则

| 规则 | 输入 | 正确输出 | 错误输出（若不处理） |
|------|------|----------|---------------------|
| 否定词 + 负面词 | 「不卡」 | POS（肯定不卡） | NEG（误判卡顿） |
| 否定词 + 正面词 | 「不好用」 | NEG | POS |
| 双重否定 | 「不是不好用」 | POS | NEG |
| 否定范围判定 | 「没有广告」 | POS | NEG |

**实现要点**：

1. 否定词表：不、没、没有、无、别、不用、从不、再也不是、毫无。
2. 否定窗口：否定词只作用于其前后 4 个字范围内的情感词。「一点都不卡」→ 翻转 → POS；「不推荐，但界面好看」→ 取主导 NEG。
3. 翻转规则：否定词 + NEG 词 → 提升一级情感；否定词 + POS 词 → 降为 NEG。
4. 双重否定：连续两个否定词 + 正面词 → POS；+ 负面词 → NEG。
5. 口语兜底：「不卡」类纯修饰表达不参与翻转。

## 四、反讽 / 反语识别指南

| 模式 | 示例 | 真实情感 |
|------|------|----------|
| 正面词 + 负面事实 | 「真棒啊，闪退了三次」 | NEG |
| 夸张肯定 + 抱怨 | 「这优化水平真是行业天花板（笑）」 | NEG |
| 反语疑问 | 「你们家的广告是比内容还多吧？」 | NEG |
| 对比反讽 | 「比十年前的我爷爷还用不明白」 | NEG |

**识别信号**：正面词典词 + 同句严重负面事实；出现「真棒/真行/真贴心/厉害」+ 转折感叹；反语疑问词（吧？/吗？）+ 负面上下文 → 送 LLM 复核。

## 五、LLM 语义复核工作流

```
原始评论 → 规则+词典初判(得分+证据词) → 置信度判定
           低置信(<0.8) → LLM 批量复核(≤200条) → 输出结果
           高置信(≥0.8) → 直接输出
```

### 需送 LLM 复核的情形

1. 置信度 < 0.8（正/负面证据词冲突）。
2. 反讽信号命中（见第四节）。
3. 冲突计数：规则打分与词典得分符号相反。
4. 长文本（> 100 字的复杂句式）。
5. 无词典命中但情感明显（如「呵呵」「已举报」）。

### LLM 复核 Prompt 要点

- 输出固定 JSON：`{"sentiment":"POS|NEU|NEG|ANG","score":0~1,"reason":"一句中文理由"}`。
- 要求标注证据词与情感方向，便于审计。
- 复核结果回写词典，形成**增量学习**闭环。

## 六、置信度计算

```
置信度 = |正面词得分 + 负面词得分| / (|正面词得分| + |负面词得分| + 中性词权重)
```

- 单侧证据充分（5 负面强词、0 正面词）→ 置信度 ≈ 1.0。
- 双侧证据冲突（2 正面 + 2 负面）→ 置信度 ≈ 0.5，需 LLM 复核。
- 词典空命中 → 置信度 = 0，按文本长度与标点启发式兜底。

## 七、校准规则（版本发布场景）

| 场景 | 校准动作 |
|------|----------|
| 新版本发布首日 | 评论基数小，改用「绝对量 + 环比增幅」双阈值 |
| 评分活动期间 | 正向激增可能失真，标注 `activity_noise=true` |
| 刷评/水军识别 | 短文本 + 高频重复 + 无信息量 → 过滤不统计 |
| 跨市场渠道 | 不同商店用户画像不同，情感阈值按渠道单独校准 |
