# 反馈分类体系

> 多渠道用户反馈（客服记录 / 应用商店评论 / 社群消息 / 问卷）的统一分类标准。每个反馈样本需同时标注「一级分类」「二级分类」和「意图」，形成三层标注结构。

## 一、一级分类（7 类）

| 代码 | 一级分类 | 定义 | 二级分类 | 示例关键词 |
|------|----------|------|----------|-----------|
| BUG | 功能缺陷 | 功能不可用、报错、行为与预期不符 | 闪退崩溃 / 功能失效 / 报错异常 / 兼容问题 / 数据错误 | 闪退、白屏、报错、打不开、没反应 |
| EXP | 体验不佳 | 界面、流程、性能等体验问题 | 界面难看 / 操作繁琐 / 广告打扰 / 加载缓慢 / 耗电发热 | 广告多、卡、丑、麻烦、慢、耗电 |
| PRI | 价格争议 | 收费、价格、订阅、付费服务问题 | 价格过高 / 强制收费 / 订阅陷阱 / 乱扣费 / 退款纠纷 | 太贵、乱收费、自动续费、扣我钱、退款 |
| SER | 客服态度 | 对客服/售后服务的评价 | 响应慢 / 态度差 / 不解决问题 / 推诿 / 结果不满 | 客服不理、敷衍、踢皮球、半天不回 |
| CMP | 竞品对比 | 与同类产品比较，含迁移意向 | 对比优劣 / 迁移意向 / 推荐竞品 | 不如XX、已转XX、去用XX了 |
| SUG | 功能建议 | 期望新增或优化的功能 | 新功能需求 / 优化建议 / 交互改进 / 内容补充 | 建议、希望、能不能、求加 |
| OTH | 其他 | 无法归入以上类别 | 咨询类 / 无关内容 / 水军 / 情绪宣泄 | 请问、怎么用、哈哈 |

### 分类优先级

当一条反馈命中多个一级分类时，按优先级取主分类：**PRI > BUG > SER > EXP > CMP > SUG > OTH**

- 「新版本闪退，我想退钱」→ 主分类 PRI（涉及资金），BUG 记入 `related_categories`。
- 「客服态度差，功能也不好用」→ 主分类 SER（服务事件优先于主观体验）。

## 二、二级分类与关键词

### BUG 功能缺陷

| 二级分类 | 关键词 |
|----------|--------|
| 闪退崩溃 | 闪退、崩溃、卡死、白屏、自动退出、重启 |
| 功能失效 | 不能用、无法、失效、打不开、没反应、功能没了 |
| 报错异常 | 报错、错误码、提示失败、异常、bug |
| 兼容问题 | 安卓XX不支持、iOS旧版本、机型不兼容、平板不适配 |
| 数据错误 | 数据丢失、记录消失、金额不对、信息错乱 |

### EXP 体验不佳

| 二级分类 | 关键词 |
|----------|--------|
| 界面难看 | 丑、难看、土、颜色刺眼、排版乱 |
| 操作繁琐 | 复杂、步骤多、找不到、难用、流程长 |
| 广告打扰 | 广告多、弹窗、开屏广告、插屏、广告关不掉 |
| 加载缓慢 | 加载慢、转圈、卡顿、缓冲久 |
| 耗电发热 | 耗电、发热、烫、占内存、流量大 |

### PRI 价格争议

| 二级分类 | 关键词 |
|----------|--------|
| 价格过高 | 太贵、贵、不值、性价比低 |
| 强制收费 | 不买不能用、强制会员、只有付费才能 |
| 订阅陷阱 | 自动续费、静默扣费、取消订阅难、试用陷阱 |
| 乱扣费 | 乱扣钱、莫名扣费、多扣、扣款失败仍扣 |
| 退款纠纷 | 退不了款、申请退款被拒、退款慢 |

### SER 客服态度

| 二级分类 | 关键词 |
|----------|--------|
| 响应慢 | 半天不回、没人理、等很久、一直不回复 |
| 态度差 | 态度差、语气不好、不耐烦、敷衍 |
| 不解决问题 | 没用、不处理、应付、说一堆没结果 |
| 推诿 | 踢皮球、互相推、让我找XX |
| 处理结果不满 | 结果不满意、判我输、补偿太少 |

### CMP 竞品对比

| 二级分类 | 关键词 |
|----------|--------|
| 对比优劣 | 不如、比XX差、XX有这功能、别人家免费 |
| 迁移意向 | 已卸载、改用XX、转XX了、再也不用了 |
| 推荐竞品 | 推荐用XX、XX更好用、快跑路去XX |

### SUG 功能建议

| 二级分类 | 关键词 |
|----------|--------|
| 新功能需求 | 希望增加、求个、能不能加、需要XX功能 |
| 功能优化建议 | 建议改进、优化一下、改改、增强 |
| 交互改进 | 希望更简单、按钮大点、支持多选 |
| 内容补充 | 希望能有XX内容、增加XX模板 |

## 三、意图分类（4 类）

| 代码 | 意图 | 说明 | 识别信号 |
|------|------|------|----------|
| COM | 投诉 | 表达不满，要求解决 | 负面情感 + 具体问题 + 诉求 |
| SUG | 建议 | 提出改进方向 | 建议句式 + 中性或正向情感 |
| CON | 咨询 | 询问使用方法/规则 | 疑问句式 + 中性情感 |
| PRA | 表扬 | 认可产品/服务 | 正向情感 + 肯定词 |

### 意图判定规则

```
ANG/NEG + 具体问题对象 → COM；NEU + 疑问句 → CON
POS/NEU + 建议句式 → SUG；POS 无建议句式 → PRA；其他 → OTH 默认 CON
```

## 四、分类映射规则

### 4.1 一级分类 → 意图映射

| 一级分类 | 默认意图 | 可切换意图 |
|----------|----------|-----------|
| BUG | COM | SUG（描述「希望修复」时） |
| EXP | COM | SUG（提出具体优化方案时） |
| PRI | COM | - |
| SER | COM | - |
| CMP | COM | SUG（对比后提出建议时） |
| SUG | SUG | - |
| OTH | CON | PRA |

### 4.2 分类 → 处理流程映射

| 分类 | 处理流程 | 责任人 |
|------|----------|--------|
| BUG（P0 级痛点） | 当日建单 → 研发修复 → 回访 | 研发负责人 |
| PRI | 风控核查 → 退款处理 → 规则复盘 | 客服主管 + 风控 |
| SER | 质检回听 → 投诉升级 → 话术培训 | 客服主管 |
| CMP | 竞品建档 → 差距分析 → 产品参考 | 产品经理 |
| SUG | 需求池录入 → 评审排期 | 产品经理 |
| EXP | 体验优化池 → 版本排期 | 产品经理 + 设计 |

### 4.3 分类到痛点体系的衔接

反馈分类可映射到痛点领域（BUG→STB/FUN、EXP→PER/EXP、PRI→BIZ、CMP/SER→EXP），详见 `app-market-sentiment/resources/references/pain_point_taxonomy.md`。

## 五、标注流程与质量要求

```
原始反馈 → 清洗(去重/去水军/标准化) → 一级分类 → 二级分类 → 意图分类
        → 输出 {id, source, category_l1, category_l2, intent, sentiment, summary}
```

### 质量要求

| 指标 | 目标 |
|------|------|
| 一级分类准确率 | ≥ 95% |
| 二级分类准确率 | ≥ 90% |
| 意图准确率 | ≥ 92% |
| 抽检覆盖率 | 每月抽检 ≥ 5% 样本 |

### 冲突处理

- 自动分类与 LLM 复核不一致时，以 LLM 复核为准并记录原因。
- 同一反馈跨多分类时必须选出主分类，避免重复统计。
- 抽检发现某分类准确率低于目标，回补规则并重跑该分类数据。
