# 项目周报被动分析

## 0. 调度边界

本 Skill 只响应当前会话收到的完整派单。定时、持久状态、幂等键和主动推送归后端调度器；不得调用 `dsh-schedule`、注册 Cron、承诺未来主动联系或在业务子会话常驻。任务包必须给出 `job_id`、计划触发时间、数据 URL/快照、时间窗和输出路径。

## 1. 只读飞书读取

所有调用必须经成员专属 `promax_lark_cli` 网关（内部固定 CLI 1.0.92）。只读取用户明确给出的 spreadsheet URL；不硬编码 token、项目名、行号、负责人或时间。先调用 `sheets-workbook-info`，再调用 `sheets-cells-get`；网关不提供写操作。

## 2. 不可变输入与快照

若后端已冻结输入包，只读包内快照；若本次获准从飞书读取，读取结果必须在生产前冻结进不可变输入包，记录 URL、抓取时间、SHA256、时区和读取范围。来源编号 `SRC-*`、行/单元格证据编号 `E-*`。

## 3. 固定输出

固定为：0. job 与输入；1. 字段识别；2. 数据完整性；3. 项目进展；4. 里程碑；5. 风险分级；6. 变化（仅有可比快照时）；7. 边界真值表；8. 应由后端投递的摘要；9. 未验证项；10. 证据追溯矩阵。不得在本 Skill 内实际推送。

## 4. 风险边界

`remaining_days = planned_date - evaluation_date`。固定判定：`<0` 已延期，`0..3` 高风险，`4..7` 本周关注，`>7` 正常；未知日期为未验证。真值表必须实际代入 -1、0、3、4、7、8 或输入相关边界。

## 5. 逐项自检

- `RM-21` 完整 job_id 与触发时间存在。
- `RM-22` 未创建 Cron/常驻任务。
- `RM-23` token 与人员信息未硬编码。
- `RM-24` 数据读取或快照可追溯。
- `RM-25` 风险边界实际代入。
- `RM-26` 没有快照时不声称检测到变化。
- `RM-27` 只生成待投递摘要，不声称已推送。

遥测只由运行时 hook 产生，本 Skill 不调用 telemetry Skill，也不写凭据。
