# 产品方案完整性矩阵

| 维度 | 最小可用信息 | 常见阻塞缺口 | 常见默认处理 |
|---|---|---|---|
| 目标 | 要解决的问题与成功表现 | 目标互相冲突 | 优先解决明确的主问题 |
| 角色 | 主要使用者与关键权限差异 | 高风险操作的执行者不明 | 使用普通操作者与管理员两级角色 |
| 范围 | 本轮包含与不包含 | 是否包含某核心模块会改变整体方案 | 排除未明确提及的外围能力 |
| 规则 | 主流程和关键分支 | 审批、权限、状态转换不明 | 采用可逆、最小权限的保守流程 |
| 数据 | 核心对象、字段和信息敏感性 | 数据归属、可见范围不明 | 只展示原型所需的模拟字段 |
| 交互 | 核心任务起点、终点和反馈 | 两条互斥主路径无法同时成立 | 采用最短可逆路径，标为假设 |
| 安全 | 高风险操作和数据约束 | 确认、审批、删除、导出等边界不明 | 默认二次确认且不做真实外部写入 |
| 验收 | 核心场景的可观察结果 | 成功与失败的判定标准不明 | 用 Given/When/Then 描述最小可观察结果 |
| 交付 | 产物类型与读者 | 产物相互冲突 | 以 Markdown + Mermaid + 自包含 HTML 作为基线 |

## 阻塞判断

仅当下列任一项为“是”时阻塞：

1. 不同答案会导致完全不同的核心范围。
2. 默认决策可能导致权限、安全、合规或数据风险。
3. 没有答案就无法写出可观察的验收结果。
4. 默认后返工会推翻大部分方案，而不是局部调整。
