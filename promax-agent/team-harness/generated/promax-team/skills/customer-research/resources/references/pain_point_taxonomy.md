# 痛点分类体系（升级版：双维度分类）

> 痛点不是"客户抱怨"的同义词。本文件定义：什么算痛点、怎么分类、怎么评分、怎么排序。

## 1. 判别标准：痛点 vs 抱怨 vs 诉求

| 类型 | 定义 | 判定信号 | 处理 |
|------|------|---------|------|
| **痛点** | 造成**实际损失**（时间/金钱/效率/情绪/机会）的问题 | 有具体场景+具体后果+情绪信号 | 进入痛点清单 |
| **抱怨** | 情绪宣泄，无具体损失后果 | 只有情绪词，无场景无后果 | 降级记录，不单列 |
| **诉求** | 直接提方案（"给我一个导出按钮"） | 是解决方案而非问题 | 转需求提取（先还原问题） |

**核心判别问句**：这个表述是否描述了"客户在完成任务过程中遇到的、导致损失的障碍"？
- 是 → 痛点；否 → 按上表归类。

## 2. 双维度分类

每条痛点同时打两个维度标签：

### 维度 A：问题领域（What —— 发生在哪）

| 领域 | 说明 | 典型信号 |
|------|------|---------|
| F 功能 | 功能缺失/不完整/覆盖场景不足 | "没有"、"不支持"、"只能手动" |
| U 体验 | 操作复杂、流程繁琐、信息难找 | "步骤太多"、"找不到"、"记不住" |
| P 性能 | 慢、卡、不稳定、容量不够 | "转圈"、"崩溃"、"高峰期就挂" |
| C 成本 | 显性价格、隐性成本、性价比 | "太贵"、"额外收费"、"维护成本" |
| S 服务 | 响应慢、解决率低、专业度不足 | "找客服没人理"、"解决不了" |
| I 集成 | 对接难、兼容差、数据孤岛 | "导来导去"、"格式对不上" |
| R 合规风控 | 合规风险、权限失控、安全隐患 | "权限管不住"、"不合规" |

### 维度 B：损失类型（So what —— 造成什么损失）

| 损失 | 含义 | 示例 |
|------|------|------|
| 时间损失 | 耗时增加 | "每晚手工统计 2-3 小时" |
| 金钱损失 | 直接/间接成本 | "多订 20% 造成损耗" |
| 效率损失 | 产出受限/低效 | "高峰期排不了单" |
| 情绪损失 | 焦虑/烦躁/不信任 | "（叹气）一到月底就头疼" |
| 机会损失 | 错失商机/决策延迟 | "报表晚一周，错过调价窗口" |

## 3. 评分标准（1-5 分）

### 严重度（对客户的伤害程度）
| 分 | 标准 | 示例 |
|----|------|------|
| 5 | 阻断核心业务/直接损失严重 | "系统崩溃导致当天无法开单" |
| 4 | 显著影响日常核心流程 | "每天多花 2 小时手工操作" |
| 3 | 中等影响，可忍受但持续损耗 | "报表偶尔不准，需人工核对" |
| 2 | 轻微不便 | "界面要多点两下" |
| 1 | 偶发、影响极小 | "个别错别字" |

### 频次（受影响的程度/广度）
| 分 | 标准 |
|----|------|
| 5 | 每天发生，且所有/多数用户受影响 |
| 4 | 每周数次，或核心用户高频遇到 |
| 3 | 每月数次，部分用户 |
| 2 | 偶发（季度级别） |
| 1 | 罕见/单次 |

> 标注口径：**"提及该痛点的受访者数 / 总受访者数"** 必须随频次一并记录（如 3/8 人提及）。

## 4. 优先级矩阵

优先级 = 严重度 × 频次（各 1-5），参考阈值：

| 严重度×频次 | 优先级 | 建议动作 |
|------------|--------|---------|
| ≥ 20 | 🔴 P0 | 作为核心需求输入，优先澄清细节 |
| 12-19 | 🟠 P1 | 进入候选需求，安排二次确认 |
| 6-11 | 🟡 P2 | 记录观察，待样本扩大后复核 |
| ≤ 5 | ⚪ P3 | 存档观察，不进入本轮需求池 |

> 多受访者共识（≥50% 提及）在同等分数下**上调一档**。
> 单受访者高严重度 → 标注"个案高痛"，不直接上调。

## 5. 痛点描述书写规范

一条合格的痛点描述必须包含四要素：

```
[谁] + [在什么场景/任务中] + [遇到什么问题] + [造成什么后果/损失]
```

- ❌ "系统不好用"（无场景、无损失）
- ✅ "门店运营每晚手工汇总 300 店销量并电话下单，耗时 2-3 小时，且周末常多订/漏订造成损耗"（人+场景+问题+损失）

### 分类工作流
1. 从原始语料抽取痛点候选（脚本初筛）。
2. 用"判别标准"过滤非痛点。
3. 打双维度标签（领域+损失）。
4. 评严重度与频次（必须引用原话佐证分数）。
5. 计算优先级，按优先级排序输出。
