# 异常检测规则与算法说明

> 核心业务指标（DAU / MAU / 上传容量 / 下载容量 / 渗透率）异常检测的标准规则库。采用「统计方法 + 业务规则 + 季节/日历调整」三层过滤，减少误报。

## 一、统计方法

### 1.1 阈值法（2σ / 3σ 规则）

假设指标历史分布近似正态，以均值 ± kσ 作为异常边界：

| 规则 | 置信度 | 含义 | 触发等级 |
|------|--------|------|----------|
| 1σ | ~68% | 偏离正常范围 | 不触发（观察） |
| 2σ | ~95% | 明显偏离 | 💡 / 🟡 |
| 3σ | ~99.7% | 强烈偏离 | 🔴 |

```python
def detect_threshold(values, k=2):
    import numpy as np
    mu, sigma = np.mean(values), np.std(values, ddof=1)
    if sigma == 0:
        return None  # 数据无波动，跳过
    return {"lower": mu - k*sigma, "upper": mu + k*sigma, "z": (values[-1]-mu)/sigma}
```

### 1.2 Z-score 计算

```
z = (当前值 - 历史均值) / 历史标准差
|z| ≥ 2 → 异常（黄色）； |z| ≥ 3 → 严重异常（红色）
```

**使用要求**：
- 历史窗口建议 ≥ 28 天，剔除异常点后重算基线。
- 样本量 < 14 天时 σ 不可靠，改用中位数绝对偏差（MAD）法。
- 指标分布右偏（容量类）时，建议先取对数再计算。

### 1.3 趋势检测（线性回归斜率）

| 信号 | 判定 |
|------|------|
| 连续 3 日同向 | 趋势确立 |
| 7 日斜率超阈值 | 单调趋势预警 |
| 斜率变号 | 趋势反转信号 |

```
斜率阈值：DAU/MAU 日斜率 ≥ 2%，容量类 ≥ 3%，渗透率（周）≥ 2.5%
```

### 1.4 同比 / 环比

- **环比**：今日 vs 昨日，捕获突变（灵敏，易受噪声影响）。
- **同比**：今日 vs 上周同日，消除星期效应（推荐主用）。
- **同环比双确认**：环比超阈值 + 同比超阈值 → 高置信异常。

## 二、业务规则（硬阈值）

业务规则优先级高于统计方法，命中即触发，不依赖历史分布。

| 编号 | 指标 | 触发条件 | 等级 |
|------|------|----------|------|
| B1 | DAU | 日环比跌幅 > 20% | 🔴 |
| B2 | DAU | 日环比跌幅 > 10% 且连续 3 日 | 🟡 |
| B3 | MAU | 周环比跌幅 > 10% | 🟡 |
| B4 | MAU | 连续 2 周跌幅 > 5% | 💡 |
| B5 | 上传容量 | 日环比跌幅 > 25% | 🔴 |
| B6 | 下载容量 | 日环比跌幅 > 25% | 🔴 |
| B7 | 上传/下载成功率 | < 90% | 🔴 |
| B8 | 上传/下载成功率 | < 95% | 🟡 |
| B9 | 渗透率 | 周环比下滑 > 10% | 🟡 |
| B10 | 渗透率 | 连续 2 周下滑 > 5% | 💡 |

## 三、季节性调整

### 3.1 星期效应：工作日 vs 周末

| 产品类型 | 典型星期效应 |
|----------|--------------|
| 工具类 App | 周末 DAU 略降（5%~10%） |
| 视频/娱乐类 | 周末 DAU 显著上升（10%~20%） |
| 企业协作类 | 周末几乎归零，仅比对工作日 |
| 游戏类 | 周末活跃、充值双高 |

**处理方式**：
1. **主基线**：优先使用「上周同日」对比，天然消除星期效应。
2. **辅助基线**：使用「剔除周末的 5 日均值」作为工作日基线。
3. **周末独立建模**：周末与工作日分开建 σ 基线。

### 3.2 节假日调整

| 假日类型 | 调整方式 |
|----------|----------|
| 法定节假日（春节/国庆等） | 使用去年同期的同节假日数据对比 |
| 调休工作日 | 参照周末规律，排除出正常基线 |
| 大促/活动日 | 单独标记，不进基线样本 |

```python
def adjusted_baseline(series, calendar):
    mask = ~series.index.isin(calendar.holidays)      # 剔除节假日
    clean = series[mask]
    clean = clean[abs(clean - clean.mean()) <= 3 * clean.std()]  # 剔除异常点
    return clean.mean(), clean.std()
```

## 四、已知活动排除

活动期的指标波动属于**预期行为**，不得触发异常告警。

### 活动登记表（示例）

| 活动名称 | 类型 | 时间 | 受影响指标 | 预期影响 |
|----------|------|------|------------|----------|
| 春节红包活动 | 拉新 | 02-16~02-20 | DAU / 下载容量 | +20% |
| 会员折扣周 | 促活 | 03-01~03-07 | 付费 / DAU | +10% |
| 服务器迁移 | 技术 | 03-10 03:00~06:00 | 成功率 | -15% |

### 排除逻辑

1. 活动期间指标**不参与**基线计算。
2. 活动结束 48h 内因冲高回落产生的「下跌」**默认不告警**，需人工确认。
3. 活动效果评估单独建指标，与异常检测隔离。
4. 未登记的大幅波动 → 属于真正异常，必须告警并溯源。

## 五、检测流水线总览

```
原始数据 → 数据清洗 → 日历归一 → 活动排除 → 业务规则(B1~B10)
        → 统计方法(2σ/3σ + 趋势 + 同比环比) → 多信号合并 → 输出异常事件
```

### 合并判定规则

| 命中信号 | 判定 |
|----------|------|
| 业务规则 1 条 | 按业务规则等级直接输出 |
| 统计方法 2 条以上 | 等级提升一级 |
| 业务规则 + 统计方法 | 取最高等级并附双重证据 |
| 仅 1 条统计信号 | 💡 关注，次日复查 |

### 输出字段

```json
{
  "metric": "dau", "value": 152000, "baseline": 190000, "change": "-20.0%",
  "method": "business_rule_B1", "level": "critical",
  "evidence": ["环比-20%", "同比上周二-18%", "z=-3.2"],
  "suggested_action": "排查服务故障与负面舆情"
}
```
