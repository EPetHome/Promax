# 单 HTML 可交互原型生成

遵守 preset persona 的共享证据口径和团队文件责任；原型中的文案、数据、按钮能力、校验规则和状态变化都是产品断言，必须可追溯。负责人指定的 `source-ledger.md` 是唯一共享证据源，原型专员只写 `prototype.html`，不得修改账本或其他专员文件。

## 交付目标

- 将完整原型写入负责人指定的 `deliverables/<task-key>/prototype.html`。
- 文件名固定为 `prototype.html`，对接产物类型固定为 `kind=prototype`；不得追加时间戳、拆分资源文件或自行上传。
- 使用单个 HTML 文件，CSS 与 JavaScript 全部内联，不依赖服务器、外部图片、字体、CSS、脚本或图标库。
- 原型只演示输入支持的功能；未知或冲突功能使用可见的禁用/阻断状态，不伪造可用性。

## 执行流程

1. 读取负责人指定的 `source-ledger.md`，确认任务类型、目标路径、来源清单、`IN/CON/GAP` 编号和原型文件责任。
2. 从账本提取页面、角色、任务、字段、操作、业务校验和允许的状态转换；编号沿用账本。必要时只读核对账本列明的原始材料，发现不一致时报告负责人并阻断受影响交互。
3. 建立交互清单 `UI-xxx`，为每个页面、控件和状态转换关联 `IN/DER/DSN/FIX/CON/GAP`。
4. 页面数量由有依据的用户任务决定；不要机械补齐首页、列表、详情、设置等未提出页面。
5. 为演示必须补充的数据全部编号为 `FIX-xxx`，并在界面固定显示“示例数据，非真实信息”。
6. 对 `CON-xxx` 影响的按钮或表单设置 `disabled` 或阻断处理，显示矛盾编号和待澄清原因；不得暗中选择任一规则。
7. 写入 HTML 后回读，执行结构、脚本、交互和证据检查；失败时只修改 `prototype.html`，再复查。

## 产品与交互规则

- 只实现输入明确要求的业务操作和状态转换。
- 每个可点击按钮必须产生与输入一致的结果、导航、校验或反馈。
- 尚无依据的操作不得做成可用按钮；改用禁用控件并说明 `GAP/CON`。
- 表单校验只使用输入给出的必填、范围、数量、日期和状态规则；不得自行发明限制。
- 输入提供的字段名、枚举、数字和日期必须原样呈现或在“需求证据”面板中保留。
- 成功、错误、空状态只在对应业务条件有依据时展示；纯展示状态可用测试夹具，但必须标明。
- 不生成虚假的真实用户、订单、客户、地址、指标或经营数据。

## 页面内证据设计

原型必须提供可打开的“需求证据”区域，至少显示：

- 使用的输入事实编号与摘要；
- 测试夹具编号及“非真实信息”声明；
- 输入矛盾、受影响交互与阻断原因；
- 输入缺口和未实现功能。

证据区域服务于验收，不得被视觉样式隐藏。

## 视觉、可用性与技术规则

- 根据产品语境选择克制且一致的视觉风格；避免无意义渐变、大圆角堆叠和装饰动画。
- 使用语义化 HTML、清晰标题层级、可见焦点、表单标签和键盘可达控件。
- 支持窄屏布局；触控目标应易于操作，内容不得横向溢出。
- 所有内部导航、弹窗和表单状态必须可恢复或关闭。
- JavaScript 不访问网络、本地敏感文件、浏览器存储中的真实身份信息或外部服务。
- 页面打开时不得产生 JavaScript 错误。

## 验证与纠正

逐项检查并记录结果：

1. **文件存在**：`prototype.html` 真实存在且非空，可直接打开。
2. **单文件**：样式和脚本均内联，无 `http://`、`https://`、协议相对 URL 或外部资源依赖。
3. **脚本语法**：环境有 Node 时，对内联脚本执行语法检查；没有时标记未验证。
4. **控件盘点**：逐个核对按钮、链接、表单控件；可用控件有处理逻辑，未实现控件明确禁用。
5. **交互场景**：按输入中的正常、边界、异常和状态转换场景逐项操作；没有浏览器能力时只报告静态检查，不声称实操通过。
6. **无编造**：界面中的业务文案、规则和数据均能映射到输入事实或明确标注的测试夹具/设计选择。
7. **硬信息完整**：输入字段、数字、枚举、限制和状态可在界面或证据区域找到。
8. **矛盾阻断**：受 `CON-xxx` 影响的操作不可成功提交，界面明确说明原因。
9. **可访问与响应式**：标签、焦点、窄屏规则和禁用态存在；未做真实设备验证时明确说明。
10. **边界三点与公式求值**：对每个数值/日期阈值实际或静态核对阈值前一档、等于阈值、越界一档；数量变化动作先写 `after = before + delta`，逐行记录代入式与 true/false。证据面板的条件标签、代码判断、可见反馈必须表达同一谓词。强制代入 `before=N, delta=1` 时必须得到 `after=N+1`、`after<=N=false` 并显示拒绝反馈；不得出现标签 `before <= N`、代码 `before >= N` 拒绝且等于 N 时拒绝的自相矛盾。
11. **收缩词反证**：界面中的“仅、全部、所有、唯一、无额外、必须、不得”有直接来源或明确 DER/DSN/GAP。
12. **交接一致**：把比较符、边界反馈、状态与 CON/BLOCKED 结果整理给负责人做跨产物终审；不得自行声称其他专员文件一致。

任一项失败时修改 `prototype.html` 并从第 2 项重新检查。最终向负责人报告 `kind=prototype` 和真实路径，不得用“所有按钮可用”“移动端通过”“无控制台错误”等话术替代未实际执行的验证。
