# 业务流程图生成

遵守 preset persona 的共享证据口径和团队文件责任；图中的节点、参与者、条件、边和状态转换都属于需要追溯的断言。负责人指定的 `source-ledger.md` 是唯一共享证据源，流程专员只写 `business-diagram.md`，不得修改账本或其他专员文件。

## 交付目标

- 将 Mermaid 代码、证据映射和图表说明写入负责人指定的 `deliverables/<task-key>/business-diagram.md`。
- 文件名固定为 `business-diagram.md`，对接产物类型固定为 `kind=diagram`；不得追加时间戳、另存副本或自行上传。
- 不承诺独立预览站点或临时链接。
- 输入存在矛盾时仍生成未受影响的结构，但必须把受影响路径导向阻断节点。

## 选择图表类型

按以下顺序选择并在文件中记录为 `[设计选择 DSN-xxx]`：

1. 用户明确指定类型时，采用指定类型。
2. 多角色职责与交接是重点时，使用 `flowchart LR` + `subgraph` 表达泳道。
3. 交互先后和请求/响应是重点时，使用 `sequenceDiagram`。
4. 条件、状态或决策路径是重点时，使用 `flowchart TD`。
5. 多种视角确有输入依据时可生成多张图；不要为了显得完整重复同一内容。

## 执行流程

1. 读取负责人指定的 `source-ledger.md`，确认任务类型、目标路径、来源清单、`IN/CON/GAP` 编号和流程图文件责任。
2. 从账本提取参与者、动作、条件、顺序、状态和异常；编号沿用账本。必要时只读核对账本列明的原始材料，发现不一致时报告负责人并阻断受影响路径。
3. 为每个图元素建立映射：`N-xxx` 节点、`E-xxx` 连线、`P-xxx` 参与者，对应 `IN/DER/CON`。
4. 输入没有给出先后关系时，不自行连线；使用账本已有 `GAP-xxx`，新缺口先报告负责人。
5. 只允许补充“开始、结束、待澄清、终止受影响流程”等结构节点并标记 `[设计选择]`，不能借结构节点增加业务规则。
6. 将矛盾路径连接到 `BLOCKED(CON-xxx)：待澄清`，不得继续到任一冲突分支的成功结果。
7. 对所有数值/日期条件节点建立边界真值：阈值前一档、等于阈值、越界一档分别走哪条边；明确判断的是操作前值还是操作后值。若动作改变数量，先写 `after = before + delta`；节点必须使用可求值谓词。
8. 写入目标 Markdown，回读并验证 Mermaid 块和证据表；失败时只修改 `business-diagram.md` 后复查。

## 文件结构

```markdown
# 业务流程图：{名称}

## 0. 生成状态
## 1. 图表类型与选择依据
## 2. 参与者、节点与证据映射
## 3. Mermaid 图
## 4. 流程说明
## 5. 输入矛盾与缺口
## 6. 验证记录
```

## Mermaid 规则

- 使用标准 Mermaid 语法，节点 ID 只用 ASCII 字母、数字和下划线。
- 节点可显示简短证据标记，例如 `提交预约 [IN-004]`；完整原文放在映射表，避免图面拥挤。
- 节点名称使用动宾结构，同级粒度保持一致。
- 异常分支只在输入明确提供时生成；不得自行添加告警、重试、通知或补偿流程。
- 每条条件边必须有输入依据；未知条件写入缺口，不画成确定分支。
- 时序图中不得臆造未提供的系统、接口、消息名或返回值。
- 数据库表/字段若参与流程，原样显示并引用输入事实；不得设计新数据对象。

## 证据映射

至少包含：

| 图元素 | 显示文本 | 类型 | 来源编号 | 说明 |
|---|---|---|---|---|

结构节点的类型写“设计选择”；业务节点、角色和条件必须来自输入事实或明确推导。

## 验证与纠正

逐项检查并记录结果：

1. **文件存在**：`business-diagram.md` 真实存在且非空。
2. **语法可解析**：若环境有 Mermaid 校验能力，实际解析全部 Mermaid 块；没有时明确写“未做渲染级验证”，不能声称已渲染。
3. **元素可追溯**：每个参与者、业务节点、条件、边和状态都能在映射表定位来源。
4. **无编造节点**：输入未提供的异常、系统、通知、重试或状态没有进入图中。
5. **矛盾阻断**：所有受影响路径到达 `BLOCKED(CON-xxx)`，没有越过阻断到达成功节点。
6. **硬信息一致**：图中名称、数字、状态和字段与输入及 PRD 完全一致。
7. **版面可读**：节点文字简洁，方向一致，无孤立业务节点；因缺口刻意不连线时有说明。
8. **边界三点与公式求值**：逐个代入阈值前一档、等于阈值、越界一档，在证据表记录完整代入式与 true/false；所得布尔值必须与 Mermaid 是/否边和期望结果一致。特别检查 `delta=+1` 的上限动作：操作前允许 `before < N`，拒绝 `before >= N`；强制代入 `before=N` 时 `after=N+1`、`after<=N=false`，Mermaid 必须沿“否/拒绝”边。
9. **收缩词反证**：图和说明中的“仅、全部、所有、唯一、无额外、必须、不得”有直接来源或明确 DER/DSN/GAP。
10. **交接一致**：把条件比较符、边界反馈、状态和 CON/BLOCKED 去向整理给负责人做跨产物终审；不得自行声称其他专员文件一致。

任一项失败时修改文件并重新检查。最终向负责人报告 `kind=diagram` 和真实路径，只报告实际执行过的语法、证据和一致性检查。
