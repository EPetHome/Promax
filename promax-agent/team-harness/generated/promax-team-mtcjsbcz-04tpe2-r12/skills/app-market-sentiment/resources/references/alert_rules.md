# 预警规则配置指南

> 应用市场舆情预警规则的标准配置说明。支持三层预警等级、三类规则引擎（情感 / 指标 / 复合），内置冷却与降噪机制，避免告警风暴。

## 一、预警等级定义

| 等级 | 图标 | 优先级 | 触发动作 | 响应时效 |
|------|------|--------|----------|----------|
| 严重 | 🔴 | P0 | 即时通知全员群 + 短信升级 + 建处置群 | 15 分钟内响应 |
| 警告 | 🟡 | P1 | 通知负责人群 + 生成预警报告 | 2 小时内响应 |
| 关注 | 💡 | P2 | 记录日志 + 次日汇总 | 24 小时内确认 |

## 二、情感类规则

### 规则 S1：负面舆情爆发

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 指标 | 负面（NEG+ANG）评论占比 | 相对当日总评论 |
| 阈值 | 单日占比 ≥ 30% | 触发 🟡 |
| 阈值 | 单日占比 ≥ 45%，或 3 日内翻倍 | 触发 🔴 |
| 前置条件 | 当日有效评论数 ≥ 30 条 | 防小样本误报 |

### 规则 S2：版本问题爆发

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 指标 | 当前版本相关评论占比 | 按版本号聚类 |
| 阈值 | 新版本相关评论负面占比 ≥ 35% | 触发 🟡 |
| 阈值 | 新版本 P0 级痛点（闪退/扣费）≥ 5 条 | 触发 🔴 |
| 前置条件 | 距版本发布 ≤ 72 小时 | 版本窗口期强化监控 |

### 规则 S3：情感倾向漂移

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 指标 | 7 日滑动平均情感分 | 情感分 = (POS-NEG-2×ANG)/总评论 |
| 阈值 | 环比下降 ≥ 0.3 | 触发 💡 |
| 阈值 | 环比下降 ≥ 0.5 或连续 3 日下降 | 触发 🟡 |
| 辅助 | 情感分与星级均分同跌 → 升一级 | 交叉验证 |

```json
{
  "rules": {
    "S1_negative_burst": {
      "metric": "negative_ratio", "window": "daily",
      "levels": {"warn": 0.30, "critical": 0.45},
      "min_samples": 30, "cooldown_hours": 24
    },
    "S2_version_issue": {
      "metric": "version_negative_ratio", "window": "72h_after_release",
      "levels": {"warn": 0.35, "critical_samples_p0": 5}
    }
  }
}
```

## 三、指标类规则

| 规则 | 指标 | 阈值（默认） | 等级 |
|------|------|--------------|------|
| M1 | DAU | 日环比跌幅 > 20% | 🔴 |
| M1b | DAU | 跌幅 > 10% 且连续 3 日 | 🟡 |
| M2 | 上传/下载容量 | 环比跌幅 > 25% | 🔴 |
| M2b | 上传/下载容量 | 环比跌幅 > 15% | 🟡 |
| M3 | 渗透率 | 周环比下滑 > 10% | 🟡 |
| M3b | 渗透率 | 连续 2 周下滑 > 5% | 💡 |
| M4 | 上传/下载成功率 | 成功率 < 90% | 🔴 |
| M4b | 上传/下载成功率 | 成功率 < 95% | 🟡 |

**说明**：M1/M2 单日异常优先查故障，趋势性下滑查运营；渗透率滞后性强，谨慎判 🔴；失败率上升 + 负面评论增加 → 复合预警。

## 四、复合类规则（量价背离）

| 规则 | 条件 | 判定 | 等级 |
|------|------|------|------|
| C1 | DAU +10% 且 容量 -15%，负面平稳 | 水货用户/内容质量下降 | 🟡 |
| C2 | DAU -10% 且 容量 +15% | 头部用户依赖 | 💡（持续则升级） |
| C3 | DAU +10% 且 容量 +15% 且 负面占比 +50% | 增长伴随体验恶化 | 🟡 |

> 量价背离详细诊断逻辑见 `core-metrics-analysis/resources/references/divergence_analysis_framework.md`。

## 五、冷却与降噪策略

### 冷却时间（Cooldown）

| 等级 | 冷却时间 | 说明 |
|------|----------|------|
| 🔴 | 30 分钟 | 同规则重复触发间隔 |
| 🟡 | 6 小时 | 避免持续告警轰炸 |
| 💡 | 24 小时 | 每日最多 1 次同主题汇总 |

### 降噪（Noise Reduction）

1. **小样本保护**：评论数 < 30 条的市场，不触发百分比类规则。
2. **水军过滤**：检测到刷评（短文本高频重复），剔除后重算。
3. **活动期豁免**：营销活动导致的异常，标记 `activity_noise` 不告警。
4. **平滑窗口**：使用 3 日移动平均抑制单点抖动。
5. **同因合并**：同一根因引发的多规则触发，合并为一条主告警。

### 收敛策略

```
触发规则数 ≥ 2 且指向同一根因 → 合并为最高等级告警 + 附全部证据链
不同根因 → 分条推送，按等级从高到低排序
```

## 六、规则生命周期管理

| 阶段 | 动作 |
|------|------|
| 配置 | 按「规则-等级-阈值-冷却」四要素登记，写入 JSON 配置文件 |
| 试运行 | 新规则进入「观察期」7 天，只记录不推送 |
| 校准 | 每月基于误报率调整阈值；误报率 > 40% 必须调参 |
| 归档 | 连续 2 个月零触发的规则，评估是否保留 |

### 评估指标

- **准确率**：触发后确认问题占比 ≥ 60%。
- **误报率**：≤ 40%，否则下调灵敏度。
- **漏报率**：复盘发现未触发但确有问题的事件，需补规则。
- **响应时长**：🔴 级从触发到响应 ≤ 15 分钟。
