# 痛点双维度分类体系

> 用于应用市场用户评论（App Store / 应用宝 / 华为应用市场 / 小米应用商店等）的痛点结构化分类。
> 每个痛点样本需同时标注「问题领域」与「严重程度」两个维度，形成 6×4 分类矩阵。

---

## 一、维度一：问题领域（6 类）

| 领域代码 | 问题领域 | 说明 | 子类 | 示例关键词 |
|---------|---------|------|------|-----------|
| STB | 稳定性 | 崩溃、闪退、卡死、白屏、异常退出 | 闪退崩溃 / 卡顿死机 / 白屏黑屏 / 频繁重启 | 闪退、崩溃、卡死、白屏、无响应、重启、自动退出、死机 |
| FUN | 功能 | 功能缺失、不符合预期、逻辑错误 | 功能缺失 / 功能错误 / 交互逻辑 / 兼容性 | 不能用、没有、失效、点了没反应、功能缺失、报错、打不开 |
| EXP | 体验 | 界面、操作流程、广告、打扰程度 | 界面难看 / 操作繁琐 / 广告过多 / 推送骚扰 / 加载缓慢 | 广告太多、弹窗、界面丑、难用、操作复杂、老是提醒、加载慢 |
| PER | 性能 | 耗电、发热、流量消耗、内存占用、启动慢 | 耗电发热 / 启动缓慢 / 内存占用 / 流量消耗 | 耗电、发热、烫、卡顿、启动慢、占内存、流量跑得快 |
| SEC | 安全 | 隐私泄露、账号安全、权限滥用、诈骗风险 | 隐私泄露 / 权限滥用 / 账号异常 / 诱导下载 | 隐私、泄露、盗号、乱要权限、诈骗、扣费、恶意、摄像头 |
| BIZ | 商业 | 收费、会员、订阅、价格、内购 | 强制收费 / 价格过高 / 订阅陷阱 / 广告变现 / 充值异常 | 收费、太贵、会员、订阅、扣钱、vip、内购、充值失败、免费版 |

### 分类规则

- 一条评论可能命中多个领域，取**主领域**（占比最高、最能代表用户核心诉求的领域），辅领域记入 `related_domains` 字段。
- 命中多个关键词时按以下优先级消歧：**STB > SEC > PER > FUN > EXP > BIZ**。
  - 例：「这破软件老闪退还有广告」→ 主领域为 STB（稳定性优先）。
- 纯情绪宣泄（无具体问题描述，如「垃圾」「太差了」）归入 `EXP` 的「体验不佳」，并标记 `low_information=true`。

## 二、维度二：严重程度（4 级）

| 级别 | 名称 | 说明 | 判据 | 示例 |
|------|------|------|------|------|
| P0 | 致命 | 产品不可用或造成重大损失 | 完全无法使用 / 数据丢失 / 资金损失 / 隐私泄露 / 大面积复现（≥10% 提及率） | 打开就闪退、账号被盗、乱扣费 |
| P1 | 严重 | 核心功能受损，用户明显受阻 | 核心路径中断 / 功能失效 / 高频复现（1%~10%）/ 涉及付费功能 | 登录不上、支付失败、上传失败 |
| P2 | 一般 | 功能可用但体验受损 | 偶发问题 / 单项功能缺陷 / 界面不友好 / 广告骚扰 | 某按钮失效、广告太多、字体太小 |
| P3 | 轻微 | 瑕疵级问题，影响有限 | 个例 / 主观偏好 / 优化建议 / 文案错误 | 加载稍慢、希望增加某功能、错别字 |

### 严重程度判定要点

1. **复现频次**：同一问题被 ≥3 条独立评论提及，严重程度至少提升一级。
2. **影响范围**：涉及核心路径（登录/支付/上传/播放）自动 +1 级。
3. **经济损失**：涉及扣费、退款、付费功能失效，直接判为 P1 及以上。
4. **数据损失**：数据丢失/不可恢复，直接判为 P0。

## 三、评分规则：频率 × 严重程度

单一痛点评分公式：

```
痛点得分 = 频率系数 × 严重程度权重
```

### 频率系数

| 提及率（占当日总评论） | 频率系数 |
|------------------------|----------|
| < 1%                  | 1        |
| 1% ~ 5%               | 2        |
| 5% ~ 10%              | 3        |
| 10% ~ 20%             | 4        |
| ≥ 20%                 | 5        |

### 严重程度权重

| 级别 | 权重 |
|------|------|
| P0   | 10   |
| P1   | 6    |
| P2   | 3    |
| P3   | 1    |

### 评分示例

- 昨日 200 条评论，其中「闪退」被提及 30 条（15%），频率系数 4，级别 P0，得分 = 4×10 = **40**。
- 同日「广告太多」被提及 8 条（4%），频率系数 2，级别 P2，得分 = 2×3 = **6**。

## 四、优先级矩阵（PRI 矩阵）

将「痛点得分」映射到处置优先级：

| 得分区间 | 优先级 | 处置动作 |
|----------|--------|----------|
| ≥ 30     | P0-紧急 | 立即触发 🔴 严重预警，24h 内上报，当日拉群跟进 |
| 15 ~ 29  | P1-高   | 触发 🟡 警告，48h 内排查，输出问题定位 |
| 5 ~ 14   | P2-中   | 纳入迭代清单，随版本排期修复 |
| < 5      | P3-低   | 记录归档，作为体验优化参考 |

### 领域热点速查

| 得分区间 | STB | FUN | EXP | PER | SEC | BIZ |
|----------|-----|-----|-----|-----|-----|-----|
| ≥ 30 | 立即停更排查 | 立即修复核心功能 | 版本体验整改 | 定位性能瓶颈 | 法务+安全介入 | 商务+风控介入 |
| 15~29 | 紧急修复 | 高优修复 | 高优优化 | 高优优化 | 安全评估 | 价格策略评估 |
| 5~14 | 版本内修复 | 迭代修复 | 迭代优化 | 优化项 | 安全加固 | 运营调整 |
| <5 | 观察 | 观察 | 记录 | 记录 | 记录 | 记录 |

## 五、使用说明

- **入口**：所有应用市场评论在完成情感分析后，统一进入本分类体系打标签。
- **输出字段**：每条评论输出 `primary_domain`、`related_domains[]`、`severity`、`pain_score`。
- **统计维度**：按日/周聚合得到「痛点榜单 Top N」，与情感趋势、版本节奏交叉分析。
- **联动预警**：单一痛点得分 ≥ 15 或领域提及率环比增幅 ≥ 100% 时，触发预警评估（见 `alert_rules.md`）。
