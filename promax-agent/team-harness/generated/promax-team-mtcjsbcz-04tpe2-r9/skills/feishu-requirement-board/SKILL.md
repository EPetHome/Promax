# 飞书需求看板

## 0. 权限与输入门

只使用不可变输入清单与用户明确给出的 Base URL。所有调用必须经成员专属 `promax_lark_cli` 网关，内部固定 CLI 1.0.92；禁止 Shell、npx、HTTP API、未声明网页和落盘官方 Skill。默认只读，不创建/更新 Base、表格、视图或 dashboard。

## 1. 只读命令顺序

先用 `schema` 或 `--help` 确认参数，再依次执行 `base +url-resolve`、`+table-list`、`+field-list`、`+record-list`。记录优先输出 NDJSON 文件并核对 manifest/总数；超过上限必须继续分页或明确部分样本，不能把 `limit` 结果写成全量。

## 2. 证据与清洗

来源编号 `SRC-*`、记录/字段证据编号 `E-*`。原始 NDJSON 保持不变，清洗结果另存；文本、人员、选项和毫秒时间戳转换规则逐项记录。解析失败保留原行和错误位置，不对原始 JSON 做静默字符串替换。

## 3. 固定分析结构

固定输出：0. 输入与版本；1. 字段和口径；2. 数据完整性；3. 总需求/状态/模块/重要性统计；4. 风险与阻断；5. 记录清单；6. 边界真值表；7. 本地看板说明；8. 未验证项；9. 证据追溯矩阵。若生成 HTML，必须单文件、无 CDN/外链，图表使用原生 SVG/Canvas/CSS；不得把它计入 8 份业务产物。

## 4. 边界真值表

覆盖分页总数、时间窗、状态分类、空记录和高风险判定。每条列谓词、三点边界、代入和 E-*；无输入阈值时写不适用。

## 5. 逐项自检

- `RM-08` CLI 版本与只读风险级别已确认。
- `RM-09` 原始数据未静默改写。
- `RM-10` 统计可从记录复算。
- `RM-11` limit/分页没有制造“全量”假象。
- `RM-12` HTML 无外部依赖。
- `RM-13` 未执行任何飞书写操作。
- `RM-14` 结论均可追溯。

遥测只由运行时 hook 产生，本 Skill 不调用 telemetry Skill，也不写凭据。
