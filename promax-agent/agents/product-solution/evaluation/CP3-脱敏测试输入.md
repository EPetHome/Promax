# 脱敏测试输入：社区共享工具借用小程序

> 本案例完全虚构，不对应任何公司、客户或真实项目。业务事实、字段、规则与旧 Harness 基线输入一致；仅将交付路径改为新 preset 的固定工作区路径。

## 任务参数

- `task_type`: `all`
- `product_name`: 社区共享工具借用小程序
- `project_name`: 共享工具自助借还
- `author`: 测试产品经理A（化名）
- 必须生成三份实际文件：
  1. `deliverables/community-tool-share/prd.md`
  2. `deliverables/community-tool-share/business-diagram.md`（内含可渲染 Mermaid）
  3. `deliverables/community-tool-share/prototype.html`（单 HTML，可直接打开）

## 需求背景

某虚构社区服务站目前用纸质登记表借出锤子、螺丝刀等共享工具。希望提供一个小程序，让居民预约工具，让服务台管理员办理领取和归还。除下文明确写出的内容外，没有提供其他业务事实；未提供的信息必须标成缺口，不得自行补成确定规则。

## 用户角色

只有两个角色：

1. 已登记居民
2. 服务台管理员

本期不做居民注册、登录、身份审核和权限配置。

## 页面范围

本期原型恰好包含四个页面：

1. 工具列表
2. 工具详情
3. 我的预约
4. 管理员办理页

不得增加消息中心、数据看板、个人中心或系统设置页。

## 输入硬字段

以下是需求输入字段清单，不是数据库表设计。PRD 和原型不得默默丢弃；如果某字段不适合出现在某份产出中，要明确说明去向。

| 字段名 | 中文含义 | 是否必填 | 约束 |
|---|---|---|---|
| `tool_id` | 工具编号 | 是 | 只读 |
| `tool_name` | 工具名称 | 是 | 只读 |
| `category` | 工具类别 | 是 | 只读 |
| `deposit_yuan` | 押金金额（元） | 是 | 只读；本期不在线支付 |
| `available_qty` | 当前可预约数量 | 是 | 非负整数，只读 |
| `borrower_alias` | 借用人代称 | 是 | 2–20 个字符 |
| `reservation_date` | 预约日期 | 是 | 不早于当天 |
| `pickup_slot` | 领取时段 | 是 | 只能选“上午”或“下午” |
| `return_due_date` | 应归还日期 | 是 | 与借用期限规则一致 |
| `reservation_status` | 预约状态 | 是 | 仅允许“待领取 / 已领取 / 已归还 / 已取消” |
| `cancel_reason` | 取消原因 | 取消时必填 | 1–100 个字符 |

## 明确业务规则

- R1：每名居民同时最多有 2 条未结束预约；“待领取”和“已领取”都算未结束。
- R2：借用期限最长为 7 个自然日，从实际领取日开始计算。
- R3：居民提交预约时，若 `available_qty` 大于 0，则生成状态为“待领取”的预约；若等于 0，则提交失败并提示“当前无可预约工具”。
- R4：只有“待领取”状态可以由居民取消；取消时必须填写 `cancel_reason`。
- R5：管理员可以把“待领取”改为“已领取”，把“已领取”改为“已归还”；不允许跳过状态。
- R6：`deposit_yuan` 仅展示，本期不提供在线支付或退款能力。
- R7：本期不做消息通知、逾期提醒、续借、候补队列、评价和统计看板。
- R8：优先级只允许在有明确规则时填写；本输入没有给出 P0/P1/P2 判定规则。

## 验收场景

- A1：居民已有 2 条未结束预约时再次提交，系统拒绝并说明上限为 2 条。
- A2：`available_qty=0` 时提交，系统提示“当前无可预约工具”。
- A3：取消“待领取”预约但未填 `cancel_reason`，系统阻止取消。
- A4：居民在实际领取日后的第 14 个自然日选择 `return_due_date`，系统允许提交。
- A5：管理员尝试把“待领取”直接改为“已归还”，系统阻止操作。

## 已知矛盾

R2 规定最长借用 7 个自然日，但 A4 要求第 14 个自然日仍允许提交。两者不能同时成立。现阶段不要替需求方选择其中一个；应明确指出矛盾及受影响产出。

## 原型交互要求

- 仅实现与上述四个页面及 R1–R8、A1–A5 直接相关的交互。
- 至少让“预约”“取消预约”“确认领取”“确认归还”四类按钮产生可见反馈。
- 不调用外部接口，不加载外部图片、字体或脚本。
- 示例数据只能使用“工具A”“居民甲”等明显占位值，不得编造真实运营数据。
