# 飞书需求录入

## 0. 权限与输入门

只读取任务包列出的不可变输入清单和用户明确给出的飞书 Base URL。所有调用必须经成员专属 `promax_lark_cli` 网关；网关内部固定为 `lark-cli 1.0.92`。不得使用 Shell、`npx`、`@latest`、HTTP API 或官方内嵌 Skill 的落盘副本。

默认只读。写入必须同时满足：member_id=`requirement_management` 的机械 ACL、凭据已配置、用户对目标 Base/表格/字段/记录内容明确确认、PreToolUse 写审计门放行。任一缺失时只生成 `--dry-run`，不得加 `--yes` 或真实执行。

## 1. 闭集来源与需求结构化

为输入来源建立 `SRC-*`，为原文证据建立 `E-*`，为候选记录建立 `REQ-*`。固定字段：原文、标题、对象、场景、问题、价值、范围、一级/二级模块、重要性、状态、依赖、冲突、提出人、提出时间、链接、未知项。未提供字段保持未知，不从身份或常识补造。

## 2. 解析目标并只读探测

从用户 URL 解析 Base token；表格不明确时只读执行：

按顺序调用网关 operation：`base-url-resolve`、`base-table-list`、`base-field-list`、`base-record-list`。参数只放进网关 `input`，不得拼接命令行。

字段名以只读返回为准，语义映射必须写入报告。分页/上限未覆盖全部数据时禁止声称全量。

## 3. 冲突、重复与 ID

相似项只能标“疑似重复”，保留各自 E-*；不得擅自合并或删除。ID 格式 `REQ-yyyyMMdd-NNN` 仅在已完整读取当日记录且无并发冲突时计算；否则把 ID 留给写入端或标记待确认。

## 4. dry-run 与写入门

调用 `base-record-upsert-dry-run` 并把请求摘要、目标与哈希写入本地产物。当前网关根本不提供真实写 operation；即使第 0 节四个门齐全，也只能把真实写入移交后续已审计能力，不能自行绕开。

## 5. 边界真值表

逐条列变量、谓词、边界前/边界/边界后、实际代入和证据。至少覆盖必填字段数、分页完整性、重复候选和写入门。未知时判阻断，不以默认值偷过。

## 6. 固定输出

写入 `requirement_management.md` 的对应部分固定含：闭集输入、结构化需求表、字段映射、重复/冲突、只读结果、dry-run 请求摘要、边界真值表、真实外部动作、未执行动作、证据追溯矩阵。

## 7. 逐项自检

- `RM-01` 所有事实回到 E-* 与 SRC-*。
- `RM-02` 字段未硬编码覆盖实际 schema。
- `RM-03` 重复项未擅自合并。
- `RM-04` 分页完整性有证据。
- `RM-05` dry-run 在真实写入之前。
- `RM-06` 写入四门逐项有机械证据。
- `RM-07` 未真实调用时明确写“零真实调用”。

遥测只由运行时 hook 产生，本 Skill 不调用 telemetry Skill，也不写凭据。
