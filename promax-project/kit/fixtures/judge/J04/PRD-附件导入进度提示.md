## 2. 执行摘要

**问题**：用户上传附件后只有一个转圈图标，无法区分排队、解析、卡住；长附件等待中离开或刷新页面后进度消失；失败时没有明确提示，用户反复重传并产生重复材料。

**产品结果**：导入过程对用户可见——批次整体进度 + 每个文件的自身状态；进度与状态在切换页面、刷新后不丢失；单个文件失败不阻塞同批次其他文件，并提供"重试""退出"两个出路。

**请求的决策**：请业务 Owner 裁定第 11 节 D-01～D-07；D-01（呈现位置）直接影响页面形态，D-04（容量不足时的文件状态）直接影响状态机闭合。

## 3. 背景与问题

- 附件支持 PDF、PNG、JPG、MP3、M4A，单文件大小不超过 100MB；账号附件总容量上限 2048MB；删除的附件进入回收站，保留 30 天，**回收站中的附件仍占用账号容量**；笔记中对附件的引用在附件索引完成后才可跳转。（附件《需求说明》"二、现状"）
- 应用商店反馈与用户访谈中反复出现同一场景：上传后只有一个转圈图标，不知道是排队、解析还是已经卡住；长附件等待时间长，中途离开或刷新页面后进度消失；导入失败时没有明确提示，用户不知道成功还是失败，只能反复重传，还可能产生重复材料。（附件《需求说明》"一、背景"）

本需求只处理"导入过程的可见性"和"失败后的出路"。

## 4. 目标与成功标准

| 编号 | 目标 | 成功标准（可验证） |
|---|---|---|
| G-01 | 导入过程中，用户能看到批次整体进度与每个文件的状态 | 批次面板同时呈现整体进度与逐文件状态，取值域仅限第 8 节定义的状态名称 |
| G-02 | 解析失败时，用户能重试该文件，或放弃并退出，不阻塞同批次其他文件 | 失败文件行提供"重试"与"退出"；一个文件失败后同批次其他文件仍继续处理 |
| G-03 | 进度与状态在切换页面、刷新后不丢失，用户回来能接着看 | 刷新或切换页面后再次进入，仍能看到同一批次的当前进度与逐文件状态 |

**度量口径待定**：附件未给出量化指标（如导入完成率、重传次数下降幅度），本版不自行设定数值，作为独立开放项 D-07 记录（见第 11 节）。

## 5. 范围

**在范围**

- 导入过程的可视化：批次整体进度、逐文件状态。
- 进度与状态在切换页面、刷新后的保留与恢复。
- 单文件失败后的"重试""退出"出路。
- 容量不足时的批次级提示。
- 批次内重复文件的识别与提示。
- 导入完成后的列表刷新与引用索引状态提示（"索引中"）。

**不在范围（明确排除）**

- 批量选择入口。
- 跨批次去重。
- 回收站保留期与容量占用规则的变更（沿用现状）。
- 附件格式、单文件大小上限、账号容量上限本身的变更（沿用现状）。
- 数据库、接口、部署等技术设计。

**非目标**

- 不做导入速度优化；本需求只解决"看得见"和"有出路"。

## 6. 用户、角色与场景

| 角色 | 场景 | 关注点 |
|---|---|---|
| 普通用户（附件导入者） | 一次选择多个附件（≤20 个）导入笔记 | 还要等多久、当前卡在哪个文件、失败后怎么办 |
| 普通用户（中途离开后返回） | 导入中切换页面或刷新 | 回来是否还能看到同一批次的进度与状态 |
| 普通用户（笔记引用者） | 在笔记中点击刚导入的附件引用 | 引用是否可点击、为什么显示"索引中" |

权限：本需求不新增角色与权限，沿用现状（用户只能操作自己账号下的附件与容量）。

## 7. 业务规则（R-01～R-09，逐字沿用附件口径）

- **R-01 支持范围**：仅接受 PDF、PNG、JPG、MP3、M4A 格式，单文件不超过 100MB；不支持的格式在选择文件时提示，不进入导入队列。
- **R-02 批次**：一次导入最多 20 个文件；同一批次内按用户选择的顺序进入队列，逐文件处理。
- **R-03 进度口径**：批次显示整体进度（已完成文件数 / 批次文件总数）；每个文件显示自身状态。解析阶段的整体进度按"已解析字节 / 批次总字节"计算。
- **R-04 取消**：解析中的文件可以取消；取消后，已解析完成的部分保留，未完成的部分删除；取消某个文件不影响同批次其他文件。
- **R-05 容量判断**：导入开始时记录账号已用容量 before；文件成功写入后按 after = before + delta 更新，delta 为本次成功写入的文件大小合计；仅当 after ≤ 2048MB 时整批写入成功；若 after > 2048MB，整批不写入，批次状态标记为"容量不足"。
- **R-06 解析失败**：单个文件解析失败不阻塞同批次其他文件；失败文件进入"失败"状态，页面提供"重试"与"退出"两个操作，"重试"只处理该文件，"退出"删除该文件的临时数据。
- **R-07 失败文件暂存**：等待重试的失败文件保留 24 小时，期间不占用用户可见容量。
- **R-08 批次内去重**：同一批次内按"文件名 + 文件大小"识别重复文件，重复项给出提示并默认跳过；跨批次去重不在本需求范围。
- **R-09 索引联动**：导入完成后刷新附件列表并触发引用索引；索引未完成前，该附件在笔记中的引用显示为"索引中"，不可点击。

规则书写约定：容量阈值判断一律先算 `after = before + delta`，再判断 `after ≤ 2048MB`；本文件、流程图、原型三处使用同一写法与同一组数字（100MB / 2048MB / 20 / 24 小时）。

**本版确认的补充规则**：跨批次重复文件一律自动拦截并删除；该范围已经由需求说明确认，不再是待决定事项。

**等号边界**：after 等于 2048MB 时允许整批写入。

## 8. 状态与流转

状态名称在三份成果中逐字一致。

**批次状态（6 个）**：排队中、导入中、部分失败、已完成、容量不足、已取消

**文件状态（6 个）**：排队、解析中、已完成、失败、已取消、索引中

**批次状态流转**

| 起点 | 终点 | 触发 | 依据 |
|---|---|---|---|
| 排队中 | 导入中 | 批次开始处理首个文件 | R-02 |
| 导入中 | 部分失败 | 批次结束时仍有文件处于"失败"状态 | 假设 A-02 |
| 导入中 | 已完成 | 批次内文件全部处理完成 | R-03、R-09 |
| 导入中 | 容量不足 | `after = before + delta`，`after > 2048MB` | R-05 |
| 导入中 | 已取消 | 批次内文件全部被取消，或用户退出该批次 | 假设 A-03 |
| 部分失败 | 导入中 | 用户对失败文件点击"重试" | R-06 |
| 部分失败 | 已完成 | 失败文件重试成功或退出后，批次内无剩余失败文件 | 假设 A-03 |
| 部分失败 | 已取消 | 用户退出该批次 | 假设 A-03 |

容量不足为终止态：整批不写入。用户减少文件后需重新发起导入，形成新批次，不构成原批次的状态回退（假设 A-03）。

**文件状态流转**

| 起点 | 终点 | 触发 | 依据 |
|---|---|---|---|
| 排队 | 解析中 | 轮到该文件处理 | R-02 |
| 解析中 | 已完成 | 解析成功 | R-03 |
| 解析中 | 失败 | 解析失败 | R-06 |
| 解析中 | 已取消 | 用户取消该文件 | R-04 |
| 失败 | 解析中 | 用户点击"重试" | R-06 |
| 失败 | 已取消 | 用户点击"退出"，删除该文件临时数据 | R-06 |
| 已完成 | 索引中 | 导入完成后刷新列表并触发引用索引，索引未完成 | R-09 |
| 索引中 | 已完成 | 引用索引完成 | 假设 A-05（附件未定义索引完成后的状态名称，按已有状态"已完成"处理） |

**状态与容量的关系**：失败文件等待重试期间保留 24 小时，期间不占用用户可见容量（R-07）；回收站中的附件仍占用账号容量（现状，影响 before 的取值来源，见 D-05）。

## 9. 页面与交互要点

呈现位置（列表页内嵌 / 独立面板）为 D-01，未裁定；以下要点对两种位置都成立，原型以"附件列表页内的导入进度面板"形态演示，该形态不代表已决策。

**P1 导入进度面板**

- 顶部规则提示：R-01 支持格式与单文件上限（PDF、PNG、JPG、MP3、M4A；单文件 ≤ 100MB）、R-02 单批次上限（≤ 20 个文件）、R-05 容量判定、R-07 失败文件暂存 24 小时、R-08 批次内去重、R-09 索引中不可点击。
- 批次概览：批次状态（排队中 / 导入中 / 部分失败 / 已完成 / 容量不足 / 已取消）+ 整体进度"已完成文件数 / 批次文件总数"（R-03）。
- 解析阶段进度：按"已解析字节 / 批次总字节"显示（R-03）。
- 容量区：显示 before、delta、after 与上限 2048MB，并按 `after = before + delta` → `after ≤ 2048MB` 的顺序展示判定结果（R-05）。
- 文件列表：每行显示文件名、大小、自身状态（排队 / 解析中 / 已完成 / 失败 / 已取消 / 索引中）与可用操作。
- 失败文件行提供"重试"与"退出"（R-06）；解析中的文件行提供"取消"（R-04）。
- 重复文件行给出提示并默认跳过，可取消跳过（R-08）。
- 格式不支持的文件在选择文件时提示，不进入导入队列（R-01）。
- 笔记引用示例：索引未完成时显示"索引中"且不可点击（R-09）。

**P2 状态恢复**

- 切换页面或刷新后重新进入，仍展示同一批次的当前进度与逐文件状态（G-03）。

**状态覆盖**：空状态（尚未选择文件）、加载中（排队中 / 导入中）、错误（部分失败 / 容量不足）、成功（已完成）、取消（已取消）、禁用（"索引中"引用不可点击）均需定义。

**键盘与响应式**：所有可操作元素使用原生按钮/链接；窄屏下文件列表与容量区纵向堆叠。无障碍信号：动态状态变化通过状态区播报。

**模拟契约（原型）**：原型中的数据、进度、成功/失败、索引状态均为模拟，无真实后端与持久化；原型中的变化在刷新后不保留。原型仅做静态检查，浏览器交互未验证。

## 10. 验收要点

| 编号 | 关联 | 验收内容（Given / When / Then） |
|---|---|---|
| AC-01 | R-01 | 给定选择文件，当所选文件为 PDF、PNG、JPG、MP3、M4A 且单个 ≤ 100MB 时，则该文件进入导入队列；当格式不支持时，则在选择文件时提示且不进入导入队列。 |
| AC-02 | R-02 | 给定一次导入，当选择文件数 ≤ 20 时，则按用户选择顺序进入队列并逐文件处理；当选择文件数 > 20 时，则按 D-06 的裁定结果处理（本版未裁定，不预设行为）。 |
| AC-03 | R-03 | 给定批次处理中，则批次显示"已完成文件数 / 批次文件总数"；解析阶段整体进度按"已解析字节 / 批次总字节"计算；每个文件显示自身状态。已完成文件数的计入范围见假设 A-06。 |
| AC-04 | R-04 | 给定某文件处于"解析中"，当用户取消该文件时，则该文件变为"已取消"，已解析完成的部分保留、未完成的部分删除，且同批次其他文件不受影响。 |
| AC-05 | R-05 | 给定导入开始记录 before，当成功写入文件的 delta 使 `after = before + delta` 且 `after ≤ 2048MB` 时，则整批写入成功；当 `after > 2048MB` 时，则整批不写入且批次状态为"容量不足"。 |
| AC-06 | R-06 | 给定某文件解析失败，则该文件进入"失败"状态且同批次其他文件继续处理；页面提供"重试"与"退出"；点击"重试"只处理该文件，点击"退出"删除该文件的临时数据。 |
| AC-07 | R-07 | 给定失败文件等待重试，则其保留 24 小时，且期间不占用用户可见容量。 |
| AC-08 | R-08 | 给定同一批次内存在"文件名 + 文件大小"相同的文件，则给出提示并默认跳过重复项。 |
| AC-09 | R-09 | 给定导入完成，则刷新附件列表并触发引用索引；索引未完成前，该附件在笔记中的引用显示为"索引中"且不可点击。 |
| AC-10 | G-03 | 给定导入进行中，当用户切换页面或刷新后重新进入时，则仍能看到同一批次的当前进度与逐文件状态。 |
| AC-11 | 现状 | 给定账号存在回收站附件，则容量判断的 before 仍包含回收站附件占用（回收站附件仍占用账号容量）。 |

**假设（影响行为，需业务确认）**

| 编号 | 假设 |
|---|---|
| A-01 | 本需求沿用现状的附件格式、单文件大小上限、账号容量上限与回收站规则，不改变其取值。 |
| A-02 | 批次结束时仍存在"失败"文件，则批次状态为"部分失败"。 |
| A-03 | 批次内文件全部被取消或用户退出批次时，批次状态为"已取消"；"容量不足"为终止态，用户调整文件后重新发起导入形成新批次。 |
| A-04 | 进度与状态的保留以账号内的批次记录为基础，用户重新进入同一账号即可继续查看；不引入跨账号共享。 |
| A-05 | 引用索引完成后，文件状态回到"已完成"（附件未定义索引完成后的状态名称）。 |
| A-06 | 整体进度中"已完成文件数"计入处于"已完成"或"索引中"的文件，因索引在导入完成后触发（R-09）；附件未明确"索引中"是否计入进度。 |

**风险**

- R-05 的写入时机未明确（D-05），若为批次级一次性写入，"部分失败"批次中已成功文件是否已计入容量将无法从材料判断。
- D-01 未裁定前，页面形态无法冻结，研发交接需等待。
