# 2.1.5 字段与统计口径

复用现有明细、总统计表与历史 Skill ID；2.1.5 明细增加三种 Token 数与来源，总统计保留原 12 个公式并新增五个命中指标。发布者必须先 `prepare` 再分发；接收端 `check` 发现字段或公式缺失会报错。27个业务技能与6个角色不变。

- 运行编号：由宿主 session_id + tool_use_id 稳定派生；同一事件重放或补传不会增加调用。HTTP 幂等令牌单独使用持久化 UUID v4，以符合飞书要求。
- 任务标签：优先使用调用 args 的 product-agent-task 结构，兼容任务目录配置；父子调用继承任务名称、项目名称与业务任务类型。缺失时任务名称回退为技能名称，项目为“未填写”，任务类型为所属业务角色，不再使用会话编号、工作目录或hook。
- 任务编号：默认宿主会话派生 UUID；显式任务配置可指定 UUID；有效父上下文继续共享任务。
- 数据类型：默认正式；工作目录任务配置可显式指定测试，在 PreToolUse 固定。
- 宿主来源：WorkBuddy；fork 采集方式为原生Hook，三项内联生成能力为原生Hook-内联任务；来源判定：安装目标绑定。宿主版本独立于 Skill版本。旧来源保留兼容，历史标签迁移注明推断，无法判断写未知。
- 身份：每次安装（含测试、重装、升级）显式提供姓名、部门、工号；不可从旧 profile、用户名、历史对话推断。姓名去首尾空白后 2–5 个汉字、优先最长姓（安装包内 `runtime/现代姓氏列表.md`）且姓后至少 1 字；部门非空单行 ≤100 字；工号去空白后转大写、匹配 `^CX[0-9A-Z]+$` 且 ≤32 字。缺姓氏列表或内容为空拒绝安装。成功后 profile.researcher_id、table1 调研者编号、table3 人员编号均等于大写工号。
- 执行状态：PreToolUse 登记为运行中；fork 以完整回执结束，内联在加载后保持运行中，由 checkpoint 回报阶段、complete 明确结束。成功须有实际非空产物。回执缺失、编号不符或产物核验异常时，执行状态记为“待核验”，结果校验记为“异常”，校验说明保留具体原因；结束时间、耗时和产物数量留空，表示尚未确认，不表示没有产物。真实的业务失败或宿主工具失败仍为“失败”。这是一条 Skill 调用的状态，不是整个任务或专家成员状态；不要为修复统计重复运行业务，也不要自行改判成功。
- 产物：只上传本次技能输出目录内经核验的文件名、数量，不上传文件正文；业务 record_id 可保存在本地产物回执中。
- 结果校验为待返回、通过或异常；“通过”只代表回执格式与产物核验通过，不代表报告质量已验收。待核验记录的产物数、结束时间与耗时留空，历史失败记录不自动改写。
- 总统计的待核验次数单列；成功率、原平均耗时和总耗时只使用已确认成功／失败／取消的记录。待核验仍属于一次真实调用，不纳入成功率分母。新增「命中运行」= 已结束且缓存命中Token > 0，按 Skill ID × 数据类型（含「全部」）单列命中运行数、平均耗时秒（命中）、平均实际消耗Token、平均缓存命中Token、平均命中调用Token；四种平均均除以命中运行数，分母为 0 显示 0，不改变原 12 公式。
- 调用次数按真实 Skill 的运行编号去重；任务数按任务编号去重；人数按稳定使用者编号去重。内联整套方案只记一次真实入口执行，不为三份文件伪造三个子调用。阶段 checkpoint 与 complete 更新同一行，入口/统计查询不计。
- 同一任务包含多个技能时，总体任务数为1，不能把各技能的任务数相加；使用人数同理。
- 正式与测试在总统计表分别显示，通常各28行（全部+27技能）。正式行不随测试运行增加。
- 状态成功代表技能执行交付完成，不表示方案通过业务验收；本版未新增独立 Judge。
- 只有 readback 核验成功才叫回传成功；本地业务完成可能仍处于待传。强制退出没有结束事件时保留运行中。

## 内联阶段、产物与检查

- 本地 progress_events 保存阶段时间、产物路径 / 字节数 / SHA256 和检查结果。远端仍以同一个 run_id 更新明细，不为每份产物或每次检查创建 Skill 调用。
- 回执只接受真实 PreToolUse 已登记且 PostToolUse 已加载的内联调用；必须在本次工作目录执行。文件须在本次 artifact_dir 内且非空，检查 pass / fail 必须给实际证据文件；这些是文件和合同校验，不保证内容正确。
- checkpoint 保持运行中，已产生的业务文件数量可更新；complete 才记录结束与耗时。重复相同回执不会重复计数，结束后的文件变更不能悄悄改写旧完成记录。
- prd-document-generator 保留旧 ID，2.1.5 显示名为产品方案生成。旧远端汇总标签可能仍写 PRD 文档生成，按稳定 ID 聚合不变。版本 / 采集方式不同的平均时长和调用次数不能直接横比。
- 浏览器检查默认 not-run；草稿生成成功不表示交互验收通过。强制取消导致没有 complete 时保留未结束，不能自动猜成功；核对后可用原 run_id 关闭。

## 整包安装

- 第三张表“安装记录”：一条成功安装事件对应整个安装包，不是29条技能安装。
- 总安装次数：正式且成功的安装事件 ID 去重数；失败不计入，测试不计入。
- 安装人数：正式成功记录按人员编号去重。安装实例数按本地随机实例 ID 去重，不表示唯一硬件数量。
- 首装／重装／升级优先按同一安装实例的上次成功版本判断；尚无成功记录时，保留首次接管时读到的版本基线。基线为空为首装，与本次同版本为重装，其他版本为升级；原版本未知仍保留“未知”。失败残留的新版本文件不改变上次成功版本或基线，历史失败记录不改写。
- 安装器内部的 Windows 目录重命名重试沿用当前安装事件，不新增次数。
- 本人每次主动重装会新增安装事件，网络补传不会新增。多人电脑向同一表写明细，飞书公式统一汇总。
- 安装结果：安装中、成功、失败。失败阶段与错误类型用于定位，不上报可能包含隐私的完整异常正文。
- 安装总览仅一行正式汇总；安装明细视图显示正式事件；测试记录独立视图。旧安装不补造历史记录。
- 本人填写身份不是登录认证；工号必填且大写，同名但不同工号不合并。更换本地状态可能新增安装实例 ID。

## 人员登记（table4）

- 仅正式成功安装登记；2.1.5 每次重填身份。table4 的人员编号只有这一列是可写文本，姓名、部门和其余四列都是公式，不能手写。按顺序：① 旧编号大写后满足 CX 格式且等于本次工号 G 的唯一行命中，即便姓名不同；编号大小写不一致则覆盖。② 没有①，唯一同名 N 且旧编号不符合 CX 格式的行，覆盖旧编号为 G。③ 同名行已有不同工号，视为不同人，新开 G 行。④ 无匹配，新开 G 行，复用稳定 client_token。①或②候选多行时不覆盖，保证 G 有一行，在本地安装回执及 status 记「待人工核对」与候选编号。
- 字段：人员编号、姓名、部门、首次成功安装时间、最近成功安装时间、最近成功安装版本。姓名和部门取最近成功安装记录；成功时间以安装完成时间为准；版本按完成时间选择，不能按版本字符串排序。时间列使用飞书原生日期显示格式，接口返回日期公式序列值；如完成时间完全相同，按源表记录顺序取第一条。
- table4 的姓名、部门、时间与版本是关联 table3 的公式；可清理 table1 已完成明细，不能清空 table3 后还期待保留这些汇总。table3 安装事件保留，人员表不记录测试、失败、未安装人员或卸载状态。
- 历史覆盖仅对正式成功生效：旧编号 K 精确等值匹配 table3「人员编号」→ table1「调研者编号」→ 最后 table4 此行「人员编号」，每批最多 500 条 `batch_update`，逐批读回核对；不改其他列。回执保存 K、G、两表已更新数及状态；网络中断后按 K 重查并续改，旧编号查不到才完成。测试安装、失败安装不登记人员、不改历史。多设备新开一行时用相同编号派生幂等键；遇到重复工号行保留现状、标记人工核对，不自动删人。
- 名单只证明已收到成功安装记录；没有完整部门名册，不能自动判断哪些人没有安装。旧安装器不会新增人员登记，需更新本包；发布者可从已有正式成功事件补登记。

## Token 明细与总统计新增公式

- table1 每次真实 Skill 调用在运行结束后后台采集：按 `providerData.messageId` 去重；每次模型调用的 input=`inputTokens`，cached=`inputTokensDetails[].cached_tokens` 之和（无则 0），output=`outputTokens`。`实际消耗Token` = Σ(input − cached + output)，`缓存命中Token` = Σcached，`命中调用Token` = Σ(input + output) 仅对 cached>0 的调用。三列为数字类型 2、格式 `0`；`Token来源` 为文本类型 1，可为 `fork会话`、`内联窗口`、`未采集：<原因>`。采集不到时三个数字留空，**不写 0**。
- WorkBuddy fork 必须只认会话首行的技能目录和本次 context.run_id，算该文件全部调用；内联在成员/主会话找到本次 Skill function_call，晚于该调用且不晚于本次结束时间的调用才计入。新事件用 tool_use_id 对 callId；旧事件缺失时用结束前最后一次同名 Skill 调用；刷盘不满 60 秒暂缓，超过 24 小时找不到文件记超时。Nexus 记 `未采集：宿主不支持`。回填一次即不重算，同一运行 revision + 1 回传同一行。
- 原 12 个公式表达式保持不变。新增五个：`命中运行数 = FILTER(同数据类型且同 Skill 或全部, 状态∈{成功,失败,取消} 且缓存命中Token>0).运行编号.UNIQUE().COUNTA()`；`平均耗时秒（命中） = IF(命中运行数=0,0,命中行耗时秒.SUM()/命中运行数)`；`平均实际消耗Token`、`平均缓存命中Token`、`平均命中调用Token` 分别将命中行对应字段 `.SUM()` 除命中运行数，分母为 0 时显示 0。完整表达式以 `runtime/feishu_usage.py:formulas()` 为准，发布者运行 prepare 创建、check 核验。

## 时间口径（UTC+8）

本次执行、分析、生成、汇总报告的时间统一使用北京时间（UTC+8），输出时注明 `+08:00` 或 `UTC+8`。通过实际可用的时钟获取时间；Python 使用 `datetime.now(timezone(timedelta(hours=8)))`，不要直接使用电脑本地时间，不通过手工加 12 小时换算，不修改系统时区。已有报告、输入材料中的业务日期和原始时区按来源保留；未知时区须标注待确认，不把资料发生时间替换为报告生成时间。回传的 Unix 毫秒时间戳与耗时保持原值，不能为调整显示而偏移时间戳。

飞书 Table1、Table3 的日期字段使用原始 Unix 毫秒时间戳，Table4 的日期公式继续引用 Table3；显示与日期计算统一由统计文档的 Asia/Shanghai 时区控制。安装记录名称属于文本字段，历史文本不会随文档时区自动改写。
