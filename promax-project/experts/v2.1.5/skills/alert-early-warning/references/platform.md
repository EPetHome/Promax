# WorkBuddy 全量独立版适配

本页定义本副本的运行入口，原业务方法与参考文件继续适用。实际以本机可用工具为准，不伪造工具、凭证、调度或回执。

| 原包能力要求 | 本版实现 |
|---|---|
| 专业子智能体协作 | 专家团通过实际角色工具调度；仅 Skill 入口通过实际 Skill / fork 调用。缺少对应能力则标记未执行，返回已有成果与缺口，不冒充已派发 |
| 网页搜索、网页读取 | 使用 WorkBuddy 当前可用的联网搜索/浏览能力；没有工具则请求必要材料或记录工具失败，不伪造抓取结果 |
| 业务 Skill 使用埋点 | 当前技能自身的 scripts/feishu_usage.py，直连飞书 |
| 飞书需求池查询/录入 | 当前技能的 scripts/feishu_data.py，目标表由本次用户提供，见下文 |
| 飞书电子表格周报 | feishu_data.py 的 sheets / sheet-values；不能用 Bitable 接口读取 Sheet |
| 定时监控与提醒 | 只在用户明确要求后使用 WorkBuddy 实际可用的定时能力；没有时完成单次检查，报告定时部分未启用，不能启动旧平台命令或虚构任务 ID |
| 群、邮件、外部通知 | 须已有明确的收件人/渠道授权与可用工具；未授权时只在当前对话交付，不发给其他人 |

所有 `skills/<技能名>` 解析到这次安装的同名技能目录。原业务步骤中的相对资源路径按该业务技能根目录解析，调用 resources/scripts 下的脚本时把工作目录设为该技能根目录。产物写入用户本次任务目录，不覆盖技能文件或历史样例。

## 执行边界与中断回传

- 专业工作通过实际 Skill 调用；三项生成能力为内联执行，其余业务能力按声明 fork。内联仅加载规范不算完成，按 inline-execution.md 显式回传。缺 Skill 或所需 fork 能力则说明限制，不伪造调用。
- 工具缺失、浏览器无法启动、权限拒绝时，跳过当前不能执行的步骤并交回已有成果、原因与未验证项；可独立继续的工作继续，依赖缺失结果的部分保留待补。必需项不能因跳过而算通过。
- 使用已经可用且获准的工具。本次业务任务不为做验证临时全局安装依赖、下载浏览器或改沙箱配置；环境修复另作明确任务。权限拒绝立即停止等价重试；其它明确的临时错误最多重试一次，仍失败即返回。
- 调用工具前使用宿主支持的超时参数；单次本地验证命令默认上限 60 秒，用户明确给定的限制优先。没有硬超时 / 取消能力时如实说明；提示词不能保证中断宿主调用。因此浏览器检查移出默认生成链，不再用 CLI 试开浏览器；独立验收也仅用已确认可用的入口。命令不加 head / tail、管道或 || true 掩盖真实退出码。
- 方案生成不嵌套启动子模型或浏览器；每份成果 checkpoint 并立即回报。其它嵌套 Skill 返回部分成果或未验证报告后，父任务必须接收并汇报，不能等待全绿才结束。回传包含实际产物路径、已验证 / 未验证 / 失败项、未决问题与接续位置；完整结果合同按 collection.md。

## 证据与交付口径

- 原始材料与已确认业务规则约束本次任务；上游 Agent 的推断不自动成为事实或审批。引用给出原文位置，无人确认的取舍写“建议 / 待确认”。
- 提及记录数、独立受访人数、实际发生频率分别记录，缺失不填默认分；计算、范围与状态不得为凑模板而补造。
- 本地材料使用文件路径 + 段号 / 原始编号作为来源。只有实际联网才能写抓取时间 / 搜索结果；无证据是“未知”，明确不支持才是“缺失”。
- 正文先列结论、关键问题和待决项；证据放对应位置，避免每节重复大段免责声明。已有产物、检查结果、业务系统写入和统计回传分别报告。


## 时间口径（UTC+8）

本次执行、分析、生成、汇总报告的时间统一使用北京时间（UTC+8），输出时注明 `+08:00` 或 `UTC+8`。通过实际可用的时钟获取时间；Python 使用 `datetime.now(timezone(timedelta(hours=8)))`，不要直接使用电脑本地时间，不通过手工加 12 小时换算，不修改系统时区。已有报告、输入材料中的业务日期和原始时区按来源保留；未知时区须标注待确认，不把资料发生时间替换为报告生成时间。回传的 Unix 毫秒时间戳与耗时保持原值，不能为调整显示而偏移时间戳。

## 飞书业务读写

采集用两张表已配置，不能拿来当业务需求池。业务数据源由用户本次提供，应用需有该表权限；没有业务表权限不等于采集链路不可用，也不要换旧平台凭证绕过。

在以下命令中替换已核实的 Base token、Table ID 和输出路径。Wiki 链接如果不能直接作为 Base token 使用，需取得实际 Base token；不要猜测。

```sh
python3 "<当前技能目录>/scripts/feishu_data.py" tables --base-token '业务BaseToken' --output '/本次目录/tables.json'
python3 "<当前技能目录>/scripts/feishu_data.py" fields --base-token '业务BaseToken' --table-id '业务TableID' --output '/本次目录/fields.json'
python3 "<当前技能目录>/scripts/feishu_data.py" records --base-token '业务BaseToken' --table-id '业务TableID' --output '/本次目录/records.json'
```

records 自动分页直到完整读取。字段名与类型以 fields 为准，不能硬编码旧业务表。不要在 JSON 解析失败时改写业务原文来凑一个有效响应。

业务录入：只有用户已授权向明确目标写入明确内容时才执行；已授权的任务不重复索取确认。把实际字段对象写入 fields.json（本地文件，不回传到采集表），生成并保留一个操作 UUID，执行：

```sh
python3 "<当前技能目录>/scripts/feishu_data.py" create-record --base-token '业务BaseToken' --table-id '业务TableID' --fields-file '/本次目录/fields.json' --operation-id '操作UUID'
```

只有 status=verified 才报告已写入。重试沿用同一操作 UUID、目标与内容；响应丢失且无 record_id 时保留业务回执并核对，不能换 UUID 盲目创建。

本版不自动新建业务需求池。用户需要新池时引导在飞书创建并提供链接，或使用其已授权且实际可用的官方建表能力；不能把“采集建表成功”说成“需求池已建好”。

电子表格周报：

```sh
python3 "<当前技能目录>/scripts/feishu_data.py" sheets --spreadsheet-token '本次周报Token' --output '/本次目录/sheets.json'
python3 "<当前技能目录>/scripts/feishu_data.py" sheet-values --spreadsheet-token '本次周报Token' --range '实际sheetID!A1:Z500' --output '/本次目录/values.json'
```

读取范围须覆盖实际数据，超过当前范围时分段继续读取，不能默认 500 行就是全表。日期列按其真实含义解释。
