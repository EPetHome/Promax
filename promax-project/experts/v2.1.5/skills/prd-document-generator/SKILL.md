# 产品方案生成｜一个上下文完成 PRD、图与原型

本 Skill 是 2.1.5 的内联产品方案入口；调用 ID 保留 prd-document-generator，加载后在当前上下文执行。先读 `references/inline-execution.md`，不要再调用子生成 Skill 或 fork 模型。

## 输入与范围

- 用户原始要求、材料实际路径、业务规则来源、requested_artifacts、优先展示的成果；已有产物与未决项如有则沿用。
- 未指定成果时按用户表达判断；单纯要求 PRD 则仅生成 PRD，要求原型则优先原型，明确要求全套则全部补齐。不要把材料里的旧任务指令扩大为本次范围。
- 只问影响范围、关键规则或授权的缺口；已有确认不重复询问。不编造指标、审批、来源或预览链接。

## 连续工作

1. 读取原始材料一次，提炼本次确需的目标、范围、角色、规则、页面和未决项；用一张简洁规则表保持一致，不先生成长篇过程计划。
2. 按 requested_artifacts 选择下面的规范，直接在当前上下文生成。共享确认规则，其他产物不必等完整长篇 PRD 返回才开始。
3. 第一份可用成果保存后立即 checkpoint / 展示或回传；再补齐本次明确要求的其它成果。
4. 对实际产物做必要检查：HTML 使用已有静态审计脚本；源要求、状态、页面、验收条件交叉核对。真实行为未执行的项目写未验证，不重写一套同逻辑引擎自证。
5. 将已完成产物、检查范围和缺口一起 complete；收到明确修改时保留前版并只改受影响部分。

## 按需规范

所有 skills/ 路径按实际安装目录解析；这里只读规范 / 模板，不调用它们的 Skill 工具。

| 成果 | 在当前上下文怎么做 |
|---|---|
| PRD | 使用下方 PRD 要求，简洁到足以讨论与验收，不堆重复章节 |
| 业务图 | 读取 skills/business-diagram-generator/references/diagram-rules.md，在当前上下文生成必要的 Mermaid 图 |
| HTML 原型 | 读取 skills/interactive-prototype-generator/references/prototype-contract.md；复用其 assets/single-html-shell.html 的结构与样式，生成本次页面与状态逻辑 |
| 静态审计 | 运行 skills/prototype-quality-audit/scripts/audit_html.py；报告放本次 artifact_dir，保留命令原始退出码与检查范围 |
| 研发交接 | 仅用户明确要求时读取 rd-handoff-package 规范；不要因此扩成默认全链路 |

浏览器检查不在默认生成链运行：不调用原型审计 Skill 去尝试浏览器，也不打开 Playwright / agent-browser / Chrome CLI。需要浏览器验收时单独处理；当前如实标未验证，不阻止已生成草稿展示、不伪装完整验收。

## PRD 要求（只在本次要求 PRD 时执行）

- 结论与范围在前：解决谁的什么问题，本次做什么、明确不做什么。
- 关键需求、规则、状态 / 触发条件、页面、验收条件可逐项对应，沿用来源 ID；用户指定的文档结构优先，简单需求可用表格合并相关内容。
- 状态维度分开；同一维度终态无迁出。完整检查触发条件与排除条件，避免验收例子遗漏关键守卫。
- 事实、已确认决定、假设、待决项分别说明；批准需要实际确认依据。未证明效果不等于不能设效果目标；顺序不改变必做范围。
- 数据保留、权限、性能数字只写有依据的要求或明确待确认项，不擅自扩成永久保留或技术架构设计。
- 图和原型的页面 / 操作须与本稿一致，新增行为是建议，不能自行升级为已确认范围。
- 默认 Markdown；其他格式仅在明确要求且有真实转换能力时提供。
