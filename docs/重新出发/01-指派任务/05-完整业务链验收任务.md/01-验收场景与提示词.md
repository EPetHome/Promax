## S1｜v1 首轮

**时机：**新工作的第一条消息，附上 v1。

```text
请分析附件中的评分与反馈，交付一份简洁、可直接阅读的 Markdown 报告。

包括：
1. 评分分布与数据质量；
2. 主要反馈，附少量原文及对应 record_id；
3. 三条有依据的建议，需要进一步验证的明确标注；
4. 材料限制。

评分口径：只接受原始数值类型的1—5整数；数字字符串、布尔值及其他非法评分不计入有效评分。比例以有效评分为分母，不去重，不按日期过滤。

仅使用本次附件，不联网、不扩展为市场调研。完成必要检查并保存正式版本；如果只有草稿、保存失败或结果未知，请明确说明真实状态。
```

**看什么**

| # | 通过标准 | 对应 |
|---|---|---|
| 1-1 | 提案还没受理时，助手正文里**没有**“几秒后自动开始／已开始／正在分析”；倒计时只出现在界面上 | 阶段四 A |
| 1-2 | 成员真正开始之前，工作状态不显示成员在执行 | 阶段四 A |
| 1-3 | 首稿能看时，右侧及时出现入口 | M3 |
| 1-4 | 报告里的数字等于上面的 v1 参考值；原文引用确实存在于附件，record_id 对得上 | 统计正确 |
| 1-5 | 报告正确区分“非整数”和“越界”；如果 Judge 提出问题，打开检查报告核对它引用的原句**确实在报告里**，并且不出现“把 1.5 归入越界”这类与原文矛盾的指控 | 阶段三 |
| 1-6 | 报告如果写“某类诉求集中”却没有主题频次依据，Judge 应该指出；报告写明“只作定性举例、未统计频次”时，Judge 不应额外要求全量统计 | 阶段三 |
| 1-7 | 如果有复查关闭，检查报告能分清“已修复”和“原判断不成立（撤回）” | 阶段三 |
| 1-8 | 保存后先出现程序回执，**随后有一段业务说明**：说清成果要点、限制和入口，不复制整篇正文 | 阶段四 B |
| 1-9 | 回执不是“正式交付已完成”时，说明里**不说“已完成”**，而是讲清草稿或旧版可以看、还缺什么 | 阶段四 B |
| 1-10 | 从发送到正式完成 **≤ 5 分钟** | 效率 |

## S2｜成员运行中追问

**时机：**S1 执行中，Agent Status／主干显示有成员正在生成（不是倒计时阶段，也不是检查阶段）。

```text
请先用两三句话解释：为什么评分比例应使用有效评分作分母，而不是全部记录数？

这只是追问，不修改任务和数据，不额外派工或重新统计；原任务继续。
```

| # | 通过标准 |
|---|---|
| 2-1 | 短时间内收到公开回答，两三句话讲清分母口径 |
| 2-2 | 没有新增成员、统计或检查；原任务照常继续，不重来 |
| 2-3 | 回答里不宣称任务已完成，也不预告还没发生的阶段 |

记录：发送时刻、公开回答时刻（两者之差就是插话响应时间）。

## S3｜检查（Judge）运行中追问

**时机：**S1 执行中，状态显示“独立检查”进行中。

```text
现在进行到哪一步了？还差什么？只回答状态，不要改任何东西。
```

| # | 通过标准 |
|---|---|
| 3-1 | 回答与界面状态一致（正在检查），不说“已完成”“已保存” |
| 3-2 | 检查不被打断、不被重跑 |

> 如果执行太快没赶上检查阶段，在记录里写“未覆盖”，不要补发。

## S4｜完成后普通追问

**时机：**S1 正式完成、业务说明已经出现之后。

```text
报告里的低星比例为什么这样计算？分母为什么不是全部记录数？
```

| # | 通过标准 |
|---|---|
| 4-1 | 正常回答，口径正确（75/300＝25%） |
| 4-2 | 没有新增业务成员、统计或检查 |
| 4-3 | **不会再冒出一次交付说明**（同一回执只说明一次） |

## S6｜v2 替代更新

**时机：**S5 之后，附上 v2。

```text
附件是新版评分数据，请完整替代上一版，不要与旧数据合并。只更新受影响的统计、表述、结论和必要的关联依据，未受影响的内容保持不变；完成必要检查并保存为新版本，保留旧版，并说明这次改了什么。
```

| # | 通过标准 | 对应 |
|---|---|---|
| 6-1 | 数字等于 v2 参考值：1—5 星 31/45/74/90/60，低星 76/300＝25.33%，高星 50% | 统计正确 |
| 6-2 | 报告点到 T0076 由 3 改为 1；没有把两份数据合并成 640 条 | 替代而非合并 |
| 6-3 | 只改受影响的位置（可跨章节），未受影响的段落原样保留 | 局部修改 |
| 6-4 | 旧版仍能在版本列表中打开，内容还是 v1 的 | 版本 |
| 6-5 | 保存后的业务说明讲出**相对上一版的变化**（例如 3 星 75→74、1 星 30→31、低星 25%→25.33%） | 阶段四 B |
| 6-6 | 开始前没有“几秒后自动开始”式的预告 | 阶段四 A |
| 6-7 | 从发送到正式完成 **≤ 3 分钟** | 效率 |

## S7｜自动通知与用户消息同批（尽力覆盖）

**时机：**S6 执行中，检查快结束、状态即将从“独立检查”变成“保存”的那一刻发送。时机很难卡准，赶不上就写“未覆盖”。

```text
等一下，这次更新里低星比例具体变成多少了？
```

| # | 通过标准 |
|---|---|
| 7-1 | 你的问题得到公开回答，没有被吞掉 |
| 7-2 | 交付说明仍然只出现一次，不会因为同批而重复或消失 |
| 7-3 | 没有在保存结果出来之前就说“已完成” |

## S8｜只复查

**时机：**S6（和 S7）完成之后。

```text
报告内容不要改，只按当前版本重新做一次独立检查，确认数字和引用都对得上。
```

| # | 通过标准 |
|---|---|
| 8-1 | 不重新生成报告、不重新统计，只做检查 |
| 8-2 | 检查针对当前 v2 版本；已关闭的问题不被当作新问题重复提出 |
| 8-3 | 状态与结论如实；**已知：只复查这类交付目前没有自动业务说明**（阶段四关注 2），记下实际表现即可，不算本次失败 |

## 10. 判定口径

| 结论 | 条件 |
|---|---|
| 🟢 通过 | S1、S4、S6 全部通过；S2、S3、S5、S8 通过或有明确记录；两个时限都达标 |
