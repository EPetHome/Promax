## 4. 复核方法（Claude 在前几轮验证过的做法）

**证据只认会话记录和产物，不认 pi 的汇报。** pi 过去的偏差集中在两类：把效率改善说成设计的功劳（忽略网关尖峰）；把「结果没错」说成「可靠性没退化」（忽略中途报错）。

| 要核对什么 | 怎么取 |
|---|---|
| 解压会话 | `dsh-home/sessions/<按 cwd 命名的目录>/<会话>/session.v4.jsonl.zstd`。目录名以 `--` 开头，**shell 命令会把它当参数**，要用 Python `subprocess.run(['zstd','-dcf','--',path])` |
| Lead 与成员 | Lead 会话 id 以 `session-` 开头；成员子会话的原始文本里有「成员 xxx」（persona） |
| 每次响应的模型 | `assistant/message` 的 `data.stream` 里的 `"model"` 字段（最细）；`request/header` 每个会话只有 1—3 条，不是每次请求一条 |
| 技能目录 | 某条 `user/message` 里 `- \`技能名\`: 描述` 的列表（应为 28 个、个人技能 0） |
| 成员加载了哪些技能 | 成员会话里 `tool/call` 的 `name == "skill"`，参数里的 `name` |
| 工具清单 | `request/header` 的 `data.header.tools` |
| 报错 | `turn/end` 的 `reason.kind == "error"`，看 `reason.error.code` |
| 越界 | 所有 `tool/call` 参数里的绝对路径，只允许本运行目录、`promax-project/team/` 和系统路径 |
| 慢请求 | `step/start` 到 `assistant/message` 的时间差；输出不到 500 token 却超过 20 秒的，算网关尖峰，单列 |
| 保存 | `交付/保存记录.jsonl` 的 sha 与版本文件重算的 sha 对照 |
| 引文和数字是否编造 | 自己写脚本把成果里的「」/“” 引文、数字回材料查找；注意 Markdown 加粗、引号样式会挡住字符串匹配 |

现成脚本：`promax-eval/复核工具/review08.py`（用法 `python3 review08.py <输出目录> [10-C01 …]`，会逐会话打印成员、请求数、耗时、token、模型、调用的工具、加载的技能、联网工具、个人技能、越界、尖峰、报错、Lead 最终回答，以及保存回执）。`review07.py` 是上一轮的版本。

判断进程是否在跑时，**`pgrep -f` 的匹配串要写成 `"[.]bin/dsh --profile"`**，否则后台等待脚本会把自己也匹配进去。
