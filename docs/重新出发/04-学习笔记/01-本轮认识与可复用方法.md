# 本轮认识与可复用方法

📍 **学习材料只帮助理解和复盘，不默认变成产品运行提示词、实施授权或永久AGENTS规则。**本页仅整理本次对话和具体案例，不引用或处理用户排除的`xx-GPT6-Pro名言警句`目录。

日期：2026-09-23。实践依据见[证据索引](../02-验证记录/01-证据索引与验证边界.md)，具体问题状态见[问题总表](../03-问题清单/01-问题总表与排队关系.md)。

## 1. 从这次案例学到什么

| 认识 | 具体案例 | 下次怎样用 | 边界 |
|---|---|---|---|
| 正常结束与完整交付分开 | 草稿和PASS都有，正式保存却失败，最终仍说完成 | 分别核对执行、内容检查、保存、入口与最后说明 | 不强迫所有底层状态字段叫同一个名字 |
| 错误文本不等于根因 | 唯一标题被报不存在；20与20报不一致 | 查输入契约、版本、比较条件和实际调用顺序 | 允许先提出假设，不把假设当运行事实 |
| 原则必须落到消费者 | 已有delivery_saved=false和失败进度仍可误报 | 核对哪一步读取哪份事实、输出是否被约束 | 不等于凡事再加提示词或状态字段 |
| 程序算对不等于结论被证明 | rating_total证明不了distinct(text)和字段一致性 | 逐项说清凭证覆盖什么、不覆盖什么 | 程序也不能自动理解所有自由文本语义 |
| Judge是系统中的被评对象 | 正确范围→误报→错误返修→verified | 用独立事实／标签评价，不把PASS自产为真值 | 一个案例不能估计全业务错误率 |
| 会话身份连续与上下文全量不同 | 原Judge持续复查，同时输入峰值很大 | 保持身份和问题连续，当前输入按需整理 | 历史仍保留，关键未知与反证不能被摘要丢掉 |
| 先定位实际耗时 | 新统计仅2次，正文后却花近20分钟 | 按生成、登记、评审、提交拆解；先看当前瓶颈 | 不能把181次请求都直接算浪费 |
| 模块正确不保证组合正确 | R28—R32跨恢复、消重、schema、受理与结束 | 关键反例保留真实接口和消费者 | 隔离组合仍不等于真实模型质量验收 |

## 2. 一个行为目标怎样成为可检验的任务

```text
明确现象和期望
      ↓
保留当前输入／版本／已有结果作为基线（可以是失败）
      ↓
提出能被反证的原因假设
      ↓
按授权获取最小区分证据
      ↓
需要时做必要关联修改 → 相称验证 → 记录适用范围和剩余问题
```

例如“最后回复为什么没有披露保存失败”：若实际请求输入没有失败事实，查组装与时序；若已明确包含，查模型消费与最终展示约束。若没有请求输入记录，则结论应是无法区分，而不是重复强化同一个猜测。

最小目标不等于只能改一行或一个文件；也不等于每次同时优化模型、Judge、上下文、报告和存储。主要行为目标清楚、变化可归因，才有利于积累进展。

## 3. 信息进入上下文时要说清的事

| 信息 | 示例 | 能决定什么 |
|---|---|---|
| 用户有效要求 | v2完整替代v1，不合并 | 当前任务目标与范围 |
| 程序观察 | 某次commit返回错误；某文件字节哈希 | 对应操作／版本的事实，须结合契约解释 |
| 模型判断 | Judge认为某段不正确 | 待评审的语义判断，不自动升级为真值 |
| 原因假设 | 最后模型可能没收到失败状态 | 指导下一项区分性检查 |
| 未知／冲突 | 缺原始请求输入；两个状态字段不同 | 限定结论和下一步，不补成成功 |

“可靠上下文”包含重要未知、冲突和反证，不是只允许确定信息进入。当前有效状态也不等于最后一段聊天；来源、版本、权限与适用范围共同决定信息能支持什么。

## 4. 哪些经验现在能保留

🟢 局部候选：同版本统计共享、普通追问不派工、按record_id对照输入、保留旧稿并按必要影响更新。

🔴 负例：无依据服从错误评审、凭证挂靠无关计算、不同问题复用持久身份、保存失败后误报完成。

🟡 整轮尚不具备成功经验资格。需独立内容标签正确、正式保存成功、未解决阻断清楚、最后说明真实、记录足够完整后，再决定是否提炼正向策略。局部候选也不自动晋升规则。

## 5. 哪些内容该放在哪里

| 内容 | 应维护的位置 |
|---|---|
| 跨任务授权、命名和读取边界 | 项目AGENTS及规范模板；本次不扩写永久规则 |
| 当前实际状态与来源 | 当前基线 |
| 本轮唯一目标、允许范围与验收 | 当前基线所指的唯一指派正文；旧任务只保留历史依据，不并行维护执行要求 |
| 真正执行了什么、输出是什么 | 唯一RESULTS及原始证据 |
| 剩余问题与优先顺序 | 问题总表 |
| 本轮方法理解与反例 | 本页，按需读取 |

具体编号范围错误应成为定向反例，不能靠把它永久写进AGENTS来代替检查。开发协作方式与Promax业务运行规则分层维护，不整套复制给全部成员。

## 6. 保持全局所需的最少信息

我知道当前要交付什么；哪些行为已有证据、哪些尚未验证；这一轮只处理什么；输入、代码和结果对应哪个版本；下一步为什么能减少一个具体的不确定性。

不需要记住每个函数。需要保证：错误有定位、假设可被推翻、改动可比较、成功有证据、失败不被改写、换会话能从同一入口恢复。
