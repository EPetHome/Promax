# 产品交互设计

## 输入要求

读取产品目标、用户角色、功能编号、业务规则、数据对象、已知约束和假设清单。如果缺少会改变主路径的关键规则，返回缺口，不自行编造。

## 工作流程

1. 为每个核心角色写出“目标—起点—步骤—终点—失败恢复”任务流。
2. 生成页面地图，区分顶层导航、页面、弹窗/抽屉和局部状态。
3. 为关键页面建立状态矩阵，至少检查 default/loading/empty/error/success/disabled/permission-denied。
4. 对每个操作定义触发、前置条件、即时反馈、最终结果、失败恢复和可观察验收结果。
5. 定义键盘、焦点、模态层、表单验证、破坏性操作和响应式行为。
6. 按 `references/interaction-spec-template.md` 输出规格，使每条交互可追溯到功能编号。

## 探索与交付精度

- `exploration`：仅覆盖核心任务、页面关系、关键操作和高信息价值状态。
- `delivery`：覆盖所有 P0/P1 任务、分支、异常、权限、表单、键盘、焦点和响应式行为。

## 强制规则

- 优先使用原生 `button`、`a`、`input`、`select`、`dialog` 语义，不用可点击 `div` 代替。
- 每个表单字段都有可见标签、帮助或错误信息；不以 placeholder 代替标签。
- 危险操作要有可识别对象、影响和确认。
- 不把 hover 作为唯一的信息或操作入口。
- 状态变化不只依赖颜色，同时使用文字、图形或结构。
- 模态层打开时移入焦点，关闭后返回触发控件。

## 验证

- [ ] 所有 P0/P1 任务都有起点、终点和失败恢复。
- [ ] 所有可操作控件都有即时反馈和最终结果。
- [ ] 页面状态与业务状态没有互相矛盾。
- [ ] 所有交互规格都有来源功能编号或假设编号。

## 埋点

仅当实际产出交互规格时，调用 `telemetry-tracker` 上报 `skill=interaction-design`。埋点失败不阻断主任务。
