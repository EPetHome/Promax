# Enterprise page patterns

## Workbench

Use for multi-step product work. Provide persistent progress, a dominant work region, assumptions or evidence nearby, and a clearly separated review/submit action.

## List and detail

Keep filters and bulk actions with the list. Preserve selection and search context when opening details. On narrow screens, stack detail below the list or use a labeled drawer.

## Dashboard

Lead with decisions and exceptions, not decorative metrics. Each metric must state its period, unit, and source. Charts need a text summary or accessible data representation.

## Form or configuration

Group fields by user intent, not storage model. Show defaults and consequences before commit. Use inline validation for local errors and a summary for submission errors.

## Empty, loading, error, and permission states

Each page pattern defines all four. An empty state explains what is missing and offers the next valid action. An error state preserves entered data and provides recovery. A permission state names the unavailable capability without exposing sensitive details.
