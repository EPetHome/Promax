# 访谈框架与方法论（升级版）

> 本文件指导"如何设计并执行一次高质量的客户研究访谈"，以及"如何把原始记录整理成可分析的语料"。
> 与 pain_point_taxonomy.md、demand_extraction_rules.md 配合使用。

## 1. 研究设计（访谈之前必须想清楚）

### 1.1 目标与假设
- **研究目标**必须可检验。示例：
  - ❌ "了解客户对产品的看法"（不可检验）
  - ✅ "识别客户在订货环节花费时间最多的前 3 个任务，并评估自动化接受度"
- 写出 **3-5 条待验证假设**，访谈提纲围绕假设设计，访谈后逐条验证/证伪。

### 1.2 样本设计（B2B/B2C 通用）
| 维度 | 建议 |
|------|------|
| 样本量 | 单用户群 ≥ 5 人，3 个用户群 ≥ 15 人（饱和原则：连续 2-3 人无新信息即饱和） |
| 受访者筛选 | 覆盖：核心使用者 / 决策者 / 预算影响者 / 边缘使用者 / 流失者，至少 3 类角色 |
| 反选标准 | 排除：直接利益相关者（如竞品员工）、无使用经历者（除非研究潜在客户） |
| 记录 | 每场记录：日期、角色、时长、渠道（面对面/电话/远程） |

### 1.3 提纲设计：任务视角（JTBD）
不要按"功能清单"问，按**客户要完成的任务**问：

1. **触发**：什么情况让你开始做这件事？（找出真实动机，而非默认答案）
2. **任务**：你具体是怎么做的？一步步说给我听。（还原完整动作链）
3. **摩擦**：哪一步最让你难受/耗时/出错？
4. **现状方案**：现在你用什么都替代方案？为什么？（识别隐性竞品）
5. **期望**：如果有一个理想方案，你希望它做到什么？

> 每个主题模块都套用这五问，比笼统的"你觉得产品怎么样"有效得多。

## 2. 访谈执行

### 2.1 时间结构（60 分钟建议版）
| 阶段 | 时长 | 要点 |
|------|------|------|
| 开场 | 5min | 说明目的与保密承诺、确认可记录；先聊 1-2 个轻松话题 |
| 背景 | 10min | 角色、职责、使用频率、所在团队规模 |
| 任务还原 | 20min | 按 1.3 五问走 1-2 个核心任务，**只还原不评价** |
| 痛点深挖 | 15min | 对每个摩擦点追问"最后一次发生时具体是什么情况" |
| 方案与期望 | 8min | 现有方案满意度、理想方案描述 |
| 收尾 | 2min | 总结确认（"我理解得对吗"）、补充遗漏、致谢 |

### 2.2 提问技巧
| 技巧 | 示例 | 用途 |
|------|------|------|
| 开放式提问 | "您是怎么决定的？" | 避免引导性答案 |
| 情境还原 | "上次出错时，您当时正在做什么？" | 获取具体证据而非抽象评价 |
| 回显确认 | "我理解您是说要……对吗？" | 防误解，二次确认 |
| 沉默等待 | 提问后停顿 3-5 秒 | 鼓励受访者补充 |
| 数值化追问 | "大约多少次？多久一次？" | 为频次/严重度评分提供依据 |
| 反事实提问 | "如果没有这个功能，您会怎样？" | 探测真实依赖度 |

**禁止**：诱导性问题（"是不是觉得太慢了？"）、双管问题（"您觉得价格和功能哪个重要？"）。

### 2.3 倾听与情绪信号
- 记录**情绪信号**（叹气、停顿、重复强调、语气词），这是痛点强度的重要证据。
- 区分三类陈述（写进记录，供后续分析）：
  - **事实**："我们每周五都要手工汇总 300 家店的销量"
  - **观点**："我觉得这个系统不好用"
  - **情绪**："（叹气）一到月底就头疼"

## 3. 记录规范（决定后续分析质量）

### 3.1 记录要求
1. **原话优先**：优先保留受访者原话；必须转述时用「」标注为转述。
2. **结构标记**：按「问/答」或说话人分段，保留语气标记（如[叹气][停顿]）。
3. **证据定位**：给关键句标段号或时间戳（录音场景），供引用回溯。
4. **当天整理**：访谈后 24h 内整理，避免细节失真。

### 3.2 推荐格式（脚本可自动解析）

```
访谈日期：2026-07-10
受访者：张经理（连锁餐饮运营负责人）
访谈主题：门店订货流程
访谈渠道：远程会议
---
问：您目前门店订货是怎么做的？
答：每天夜里手工统计各店销量，再打电话给供应商下单，一般要花2-3个小时。
答：（叹气）最怕周末销量波动，经常多订或少订，浪费很多。
```

### 3.3 语料整理三原则
- **不脑补**：受访者没说的，不替他说。
- **不合并**：多个受访者的内容不混为一条记录。
- **可回溯**：任何一条被引用的证据都能定位到"哪份记录、哪一段"。

## 4. 访谈伦理与三角验证

### 4.1 伦理
- 开篇说明目的与保密承诺，取得记录许可。
- 不诱导、不评价受访者观点（"这个方法不对"绝不能说）。
- 数据脱敏：输出中隐去可识别个人/公司名称（可用代号）。

### 4.2 三角验证（提升可信度）
| 验证方式 | 做法 |
|---------|------|
| 多人验证 | 同一结论出现在 ≥2 个独立受访者 → 标记"共识"；单访 → "个案" |
| 行为验证 | 观点 vs 实际行动（用替代方案/花钱）一致 → 可信度高 |
| 数据验证 | 与后台使用数据/客服记录交叉核对（属其他环节，但可作为交叉线索标注） |

## 5. 常见坑与规避

| 坑 | 规避 |
|----|------|
| 只记录观点不记录事实 | 强制记录"具体做了什么" |
| 把解决方案当需求 | 追问"你为什么要这个？想解决什么？"（见需求提取规则） |
| 受访者礼貌性好评 | 用行为证据检验（是否愿意推荐/付费） |
| 以偏概全（1 人说 = 全体需求） | 标注"个案"，不升级为共识 |
| 丢失出处 | 引用必须带记录编号+段落/时间戳 |
