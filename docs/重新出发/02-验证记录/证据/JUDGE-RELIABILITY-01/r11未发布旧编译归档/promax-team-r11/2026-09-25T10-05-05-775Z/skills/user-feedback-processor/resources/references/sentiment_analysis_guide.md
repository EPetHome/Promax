# 情感分析指南与校准规则

> 多渠道用户反馈（应用商店 / 客服记录 / 社群 / 问卷）情感分析指南。与 `app-market-sentiment` 的情感框架同源，本文档侧重**多渠道差异校准**与**语境感知**。

## 一、四级情感模型

| 等级 | 代码 | 分值 | 说明 | 示例 |
|------|------|------|------|------|
| 正向 | POS | +1 | 满意、认可、表扬 | 「处理很快，很满意」 |
| 中性 | NEU | 0 | 客观描述、咨询、无情绪 | 「请问会员怎么退订」 |
| 负向 | NEG | -1 | 不满、抱怨、失望 | 「等了三天没解决」 |
| 愤怒 | ANG | -2 | 强烈不满、辱骂、投诉升级 | 「骗子！再不退款就投诉！」 |

> 情感是**意图的输入而非结论**：ANG/NEG 默认导向投诉意图，但需结合分类体系综合判断（见 `classification_taxonomy.md`）。

## 二、关键词词典

### 2.1 通用词典（全渠道通用）

| 情感 | 关键词 |
|------|--------|
| POS | 满意、好用、感谢、谢谢、辛苦、点赞、表扬、好评、迅速、解决、开心、nice |
| NEU | 请问、如何、怎么、咨询、一般、还行、可以用、正常 |
| NEG | 不满意、难用、没用、卡、慢、敷衍、失望、差评、不行、没法用 |
| ANG | 垃圾、骗子、恶心、投诉、举报、滚、坑人、垃圾公司、还钱 |

### 2.2 渠道扩展词典

| 渠道 | 附加词 |
|------|--------|
| 客服对话 | 等这么久、没处理、重新说一遍；麻烦您、帮帮我、求求你们 |
| 应用商店 | 更新后、新版、闪退；一星、差评、卸载 |
| 社群/微博 | yyds、绝绝子、破防、避雷、劝退、散了吧 |
| 问卷 | 非常满意/比较满意/不太满意（按分值映射） |

## 三、否定与转折处理模式

### 3.1 否定模式

| 模式 | 例句 | 处理 |
|------|------|------|
| 否定 + 负面词 | 「不卡了」 | 翻转 → POS |
| 否定 + 正面词 | 「一点都不好用」 | 翻转 → NEG |
| 双重否定 | 「不是不好用」 | 翻转 → POS |
| 否定 + 名词 | 「没有广告」 | 语义正向 |
| 部分否定 | 「功能能用，就是广告多」 | 分句打分，整体取负向主导 |

**否定词表**：不、没、没有、无、别、甭、从不、毫无、并非、不至于。
**作用范围**：前后 4 字窗口，超出范围的情感词不参与翻转。

### 3.2 转折模式

| 转折词 | 含义 | 打分方式 |
|--------|------|----------|
| 但是/可是/不过/然而 | 后句为主 | 后句权重 ×1.5 |
| 虽然/尽管 | 前句让步 | 前句降权 ×0.5 |
| 除了/只不过 | 轻微转折 | 忽略让步部分，取主句 |
| 而且/并且/还 | 递进 | 多句情感累加 |

示例：「虽然界面一般，但是客服处理很快」→ 让步段降权，主体为 POS。

### 3.3 程度副词

| 程度 | 副词 | 加权系数 |
|------|------|----------|
| 极度 | 非常、极其、太、超级、巨、简直 | ×1.8 |
| 比较 | 挺、蛮、有点、比较、还算 | ×1.2 |
| 轻度 | 稍微、些许、勉强 | ×0.8 |

## 四、语境感知分析规则

情感判断必须结合**语境**，脱离语境会产生系统性误判。

### 4.1 客服对话语境

- 客服回复中的「抱歉」是客套话，不视为用户负向；「好的」「知道了」→ 中性。
- 「那好吧」「行吧」→ 隐含不满的勉强同意，判 NEG 轻级。
- 首条与结尾消息各加权：结尾表达最终情绪，权重 ×1.3。

### 4.2 应用商店语境

- 「一般」「还行」在五星评分下通常是不满信号，映射 NEU~NEG。
- 一星+投诉 → ANG；三星 → NEU；四星+抱怨 → NEG 轻级。
- 纯版本号评论（「1.2.3」）过滤；「好评」需确认表达意愿而非描述行为。

### 4.3 社群/社媒语境

- 反讽高频出现，正面词 + 负面事实组合必须送 LLM 复核。
- 表情符号参与判断：🙃/😅 多为负面反讽。
- 转发类内容（「转」/「@」）默认不表达本人情感 → NEU。

### 4.4 问卷语境

- 量表题直接按分值映射，不跑词典。
- 开放题结合题目上下文（「最需要改进的是」→ 内容多为负向建议，按 SUG 处理）。

## 五、渠道差异化校准

不同渠道用户表达习惯、情绪烈度差异显著，**各渠道单独建基线**。

| 渠道 | 负面基线（近 30 日中位） | 烈度说明 | 校准规则 |
|------|--------------------------|----------|----------|
| 应用商店 | 20%~30% | 整体偏负，含大量一星发泄 | 突破基线 +15pp 才算异常 |
| 客服记录 | 8%~15% | 用户相对理性，问题导向 | 负向占比 > 25% 需高度关注 |
| 社群/微博 | 5%~12% | 表达自由，反讽多 | ANG 占比单独统计 |
| 问卷 | 依量表而定 | 结构性分布 | 按分值分析，不做阈值预警 |

### 渠道权重（多渠道汇总时使用）

```
应用商店 0.4（量大）｜客服记录 0.3（准确）｜社群/微博 0.2（声量大）｜问卷 0.1（结构样本）
```

### 渠道间矛盾处理

- 商店负面高、客服负面低 → **体验性问题**，用户在商店发泄而非找客服。
- 客服负面高、商店低 → **服务流程问题**，优先查客服侧。
- 社媒声量大但负面占比低 → 营销声量正常，不必恐慌。
- 多渠道同时负面上升 → 真实重大负面事件，触发 🔴 预警。

## 六、LLM 语义复核工作流

```
规则打分 → 置信度计算 → 高置信直接输出
                     → 低置信/反讽/长文本/多分类冲突 → LLM 复核
```

### 触发复核条件

1. 置信度 < 0.8（情感证据冲突）。
2. 反讽信号命中（正面词 + 严重负面事实）。
3. 文本 > 100 字，或客服对话整段分析。
4. 渠道内情感分布偏离基线 2σ。

### LLM 复核输出格式

```json
{"sentiment":"NEG","score":0.9,"evidence":["广告太多","一直闪退"],
 "reason":"同时存在广告骚扰与闪退两个负面事实",
 "sarcasm":false,"confidence":0.95}
```

### 质量监控

| 指标 | 目标 | 监控方式 |
|------|------|----------|
| 情感准确率 | ≥ 92% | 每周抽检 200 条人工核对 |
| 反讽检出率 | ≥ 80% | 标记样本专项复核 |
| 渠道均衡 | 各渠道准确率差 ≤ 5pp | 分渠道统计 |
| 新增规则命中 | 复核回写规则命中率 ≥ 60% | 记录追踪 |
