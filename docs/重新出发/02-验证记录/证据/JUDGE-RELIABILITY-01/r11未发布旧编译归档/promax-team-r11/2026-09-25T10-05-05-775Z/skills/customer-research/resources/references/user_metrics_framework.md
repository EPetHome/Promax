# 用户指标体系（Metrics Framework）

> 目的：给客研结论一个"可测量"的锚——痛点/需求都能映射到具体指标，支持定性定量互证。
> 借鉴：规模 × 价值交叉诊断（量价背离）、HEART 框架。指标定义仅供参考，实际以产品口径为准。

## 一、指标分类框架

### 1. 规模指标（用户侧）——"有多少人"
| 指标 | 定义 | 客研解读 |
|------|------|---------|
| DAU / MAU | 日/月活跃用户数 | 用户规模与粘性（DAU/MAU 比值=粘性） |
| 新用户数 / 留存 | 新增、次日/7日/30日留存 | 拉新质量、体验是否留住人 |
| 付费用户数 | 交易/订阅用户 | 需求真实度的最强信号 |
| 使用/覆盖人数 | 某功能的使用用户数 | 功能需求范围 |

### 2. 价值指标（资源侧）——"用了多少"
| 指标 | 定义 | 客研解读 |
|------|------|---------|
| 使用量/容量 | 上传下载量、调用量、订单量 | 使用深度 |
| 交易额 / ARPU | 收入、人均贡献 | 商业价值 |
| 人均使用量 | 总量/活跃用户数（衍生比率） | 质量 vs 数量 |

### 3. 行为指标（过程侧）——"怎么用的"
| 指标 | 定义 | 客研解读 |
|------|------|---------|
| 功能使用率 | 用某功能的人数占比 | 需求强度、功能边缘化预警 |
| 使用频次/时长 | 打开次数、停留时长 | 习惯养成度 |
| 转化率 | 各环节漏斗 | 卡点定位（配合访谈找原因） |
| 任务完成率 | 目标任务成功率 | 可用性痛点 |

## 二、量价背离诊断（核心技巧）

**用户数（量）与使用量/容量（价）交叉**，四象限解读：

| 情形 | 解读 | 客研动作 |
|------|------|---------|
| 用户涨、容量跌 | 警惕"水货用户"（拉新质量差） | 访谈新用户动机与首用体验 |
| 用户跌、容量涨 | 警惕"大户依赖"（流失散户） | 访谈流失散户原因 |
| 双涨 | 健康增长 | 深挖增长驱动（验证画像） |
| 双跌 | 产品价值下滑 | 访谈+舆情定位根因 |

> 用法：指标异常 → 作为"定量线索"发起访谈（解释序贯）；访谈发现 → 到指标里找"规模证据"（探索序贯）。

## 三、HEART 框架速查（Google 用户体验度量）

| 维度 | 回答 | 代表指标 | 客研衔接 |
|------|------|---------|---------|
| H Happiness 愉悦 | 用户感受如何 | NPS、满意度、情绪分析 | 访谈情绪信号、舆情情感 |
| E Engagement 参与 | 用得深不深 | 使用频次、时长、DAU/MAU | 行为特征画像 |
| A Adoption 采纳 | 多少人开始用 | 新用户、注册转化 | 新功能需求验证 |
| R Retention 留存 | 留住多少人 | 留存率、流失率 | 流失痛点访谈 |
| T Task Success 任务达成 | 事办成没有 | 任务完成率、出错率 | 可用性痛点 |

## 四、痛点/需求 → 指标映射（访谈到数据的桥）

| 访谈发现类型 | 可映射指标 | 验证方向 |
|-------------|-----------|---------|
| "手工统计耗时 2-3 小时" | 任务耗时、人均产出 | 自动化后耗时下降 |
| "周末经常多订少订" | 订单误差率、损耗率 | 智能预测后误差下降 |
| "批量导入很需要" | 功能使用率、导入频次 | 上线后使用率达标 |
| "对账特别痛苦" | 对账时长、出错率、工单量 | 对账相关工单下降 |
| "客服响应慢" | 首次响应时长、满意度 | 优化后指标改善 |

## 五、输出约定

- 客研报告每条痛点/需求，如可映射指标，附「验证指标 + 预期方向」。
- 多源互证时（triangulation_guide.md），指标证据只用于**佐证方向**（升/降/达标），不冒充因果证明。
- 指标口径不确定时标注"口径待确认"，不编造数值。
