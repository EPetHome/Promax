## 2. 目标和边界：这是预期，不是完成情况

项目资料描述的稳定主线是“目标—材料—成果—独立评审—持续修改”；模型负责专业判断，程序维护权威事实与执行约束。普通问答不必调用全队，成果任务按需要组织成员。

建议当前收口场景：评分报告首次生成 → 同一工作的普通追问 → 修正版数据替代及必要更新。是否采用及其具体范围由现役任务和用户决定。

暂不因本次收口重定义全部产品架构，或把六类业务同时纳入一轮修复。记录性能不等于同时授权修改模型、上下文、调度和报告模板。

失败运行也能成为基线。基线的用途是定位、比较和限定结论，不是宣称系统已经合格。随机性较强的任务，不要求每次结果完全相同，但必须记录条件与全部尝试。
