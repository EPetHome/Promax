## 七、设计约束（陷阱）

1. **逐字替换**：用脚本替换，断言原文恰好命中 1 次；替换后同一行其余文字逐字节不变。
2. **会话 ID**：多轮的第 2—4 轮必须带首轮的会话 ID，否则会开一个新会话，整个多轮测试作废。每轮跑完先核对 `events-<标签>.jsonl` 第一行的 `sessionId` 和首轮一致，再跑下一轮。
3. **v2 附件的时机**：`评分样本-v2.json` 只能在第 2 轮（追问）结束之后、第 3 轮开始之前复制进去，不要在建目录时就放。
4. **v1 版本文件不能被改**：第 1 轮结束后先记下 `交付/版本/v1-*.md` 的 sha256，第 3 轮后再算一次，必须相同。
5. **会话结构**：Lead 会话在各轮之间是同一个会话（事件会追加）；每一轮派的成员都是新的子会话。按时间窗把 Lead 的调用分到各轮（用各轮 `timing` 和事件时间），不要按会话 id 字典序排。
6. **会话目录名以 `--` 开头**：解压用 Python `subprocess.run(['zstd','-dcf','--',path])`。
7. **`bg_run` 外层退出码 0 不代表 dsh 成功**：以 `timing-*.json` 的 `exit_code` 和会话 `turn/end` 为准。
8. **M6 必须全量**：扫全部会话的全部 `tool/call` 参数，相对路径按命令的 cwd 解析；`/dev/null` 不算越界。
9. **进程检查**：`pgrep -f "[.]bin/dsh --profile"`，记录返回码。
