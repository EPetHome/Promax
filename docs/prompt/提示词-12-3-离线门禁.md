## 七、设计约束（陷阱）

1. **委派深度 2**：fork 是成员的子会话，测试 profile 里放开 `subagent.maxDepth: 2`。
2. **不要用 headless 运行器**（Lead 第一次空闲就退出）；用常驻运行器，「做完」= 根空闲 + 无成员在跑 + 安静期。门禁里安静期可以缩短（例如 3 秒），写进 README。
3. **隐藏断言**：G10 检查模型收到的工具清单（会话的 `request/header`），不能只看配置。
4. **空插件**：被测文件不存在时，门禁要写出「模块缺失」的 FAIL 报告并退出 1。
5. **路径**：门禁在 Loop 的候选副本里运行，被测插件用 `{code}` 下的相对位置找，不能写死 `~/.loop040/promax-n2/source`。
6. **确定性**：同一门禁连跑两次，断言结果一致。
