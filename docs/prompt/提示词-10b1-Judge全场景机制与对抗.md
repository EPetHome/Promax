## 六、改造规格

### 6.1 编号口径（修 R10-1 规格问题 1）

带编号引文的来源编号 = 括号开头**连续的**编号（用空格、`、`、`，`、`,`、`；`、`;` 分隔）；遇到第一个不是编号的词就停，后面的说明文字里即使出现编号也不算来源。`"原文"（T0006，与 T0001 同句）` 的来源只有 T0006，应判 mismatched；`（T0001 T0006）`、`（T0001、T0006，2 星）` 仍是两个来源。

### 6.2 检查组与台账

1. **检查组**：一次 Judge 检查的对象，可以是一个文件或一组文件（C04 三件套）。组名 = 第一个被审文件的文件名去掉扩展名。
2. 该组的全部检查文件放在 `交付/检查/<组名>/`：`precheck-r<轮次>.json`、`draft-r<轮次>.json`、`ledger.json`、`检查.md`。不同组的台账、轮次、复查范围、报告完全独立。
3. `precheck.py <被审文件...> --kind <成果类型> [--facts <facts>] [--previous <上一版文件...>] --sources <材料...>`：可接多个被审文件；`--kind` 取 rubrics.yml 的节名（三件套用 `prd`，程序按扩展名和内容再识别流程图、原型）。
4. `issues.py submit <草稿>`：草稿 `target` 可以是字符串或字符串数组；原句必须逐字存在于组内任一文件；每个文件的 sha256 都记入台账；PASS 须组内每个文件都有本轮预检且 sha 一致。`issues.py show [<组名>]`：带组名打印该组；不带时列出全部组的一行摘要。
5. **没有 `--kind` 的旧用法保持 10a 行为**（`交付/检查/` 根目录、10a 的引文覆盖规则），10a 的离线用例必须仍然全过。

### 6.3 引文按来源类型核对（D10）

1. **来源标签**，程序运行时从材料推出，不写死：JSON 记录里以 id 结尾的字段值（现有）；文件名里符合编号写法的片段（`访谈-IV-01-学生.md` → `IV-01`）；CSV 中表头以「编号」或 id 结尾的列的值（跳过表头前的说明行）；文件名去掉常见前缀后的主体名（`竞品-墨舟笔记.md` → `墨舟笔记`）。
2. 引号后括号的第一个词命中某个来源标签 → 算「可归属引文」：原文必须在该来源里逐字存在，否则 missing；在材料里但不在该来源 → mismatched。
3. **可核对覆盖**：按成果类型计算。评分、客研、竞品、需求类 = 可归属引文数；`requirement-review-report` = 在被评审文件里逐字找到的引文数；`prd`、`diagram`、`prototype` = 不计算（引号里是界面文案），也不适用覆盖规则。
4. PASS 拒收规则改为：成果类型计算覆盖、引号数 > 0、可核对覆盖 = 0 → 拒收。错误信息写明类型、引号数和原因。

## 七、设计约束（陷阱）

1. **防止照着样本写程序**：程序里不得出现样本或场景专用的字符串、编号、文件名、竞品名、状态名；一切从输入推出。验收会 grep `kit/fixtures`、`promax-eval/fixtures` 里出现的专有词。所有 K 检查还要在 9.2 的历史成果上跑，**逐条标出误报**。
2. **先写答案、冻结，再真跑**：每份对抗样本和答案写完后记录 sha256 到 `分析-10b1/样本冻结.json`；之后不得再改样本或答案。若发现样本有错，新建样本号，旧的保留并在简报说明。
3. **样本的埋错要有两类**：每份至少 4 处错误，其中至少 1 处由程序检出（K 检查或引文核对）、至少 2 处只能由 Judge 语义判断（参考该场景答案里的埋点类别：个案写成普遍、矛盾被抹平、传闻当证据、方案当需求、资料未提及写成不支持、主观夸张当优势、依赖方向反了、合并丢编号、after 公式错、失败无出路、把正确写法判成缺陷……）；另外至少 1 处**陷阱**（正确但容易被误判的内容）。
4. **样本底稿**：从 2.2 列出的正式版本复制后改写；样本放 `kit/fixtures/judge/<样本号>/`，答案只放 `promax-eval/fixtures/judge/<样本号>/答案.md`（格式照 `promax-eval/fixtures/B4/答案.md`：埋点、位置、应由程序还是 Judge 检出、陷阱、通过标准）。
5. **J05（评审）要附被评审的 PRD**：C05 的 `待评审PRD-分享链接权限设置.md` 原件作为材料；埋错包括「把正确写法判成缺陷」（参考 C05 答案的 T1）和引用了 PRD 里不存在的原句。
6. **J07（L01 链路）**：附件含 L01 的原始材料 + 痛点清单 + 需求池优先级 + PRD 三份成果，用户要求「对三份成果分别做独立检查」；埋错要覆盖上下游不一致（例如 PRD 的需求编号不是优先级第一）。Lead 应派 3 个 judge、得到 3 个检查组。
7. **向后兼容**：没有 `--kind` 时行为与 10a 完全一致；10a 离线用例（Q1—Q5）必须全过。
8. **CSV**：表头前有说明行，编码 UTF-8；不能把说明行当表头。
9. 会话目录名以 `--` 开头，解压用 `subprocess.run(['zstd','-dcf','--',path])`；以 `timing-*.json` 的 `exit_code` 和 `turn/end` 为准判断运行成败。
10. **报错全表**：扫全部 `tool/result`，含 `Traceback`、`Error:`、非 0 退出、`"accepted": false` 的都记，即使后面成功了；issues.py 拒收单列。
