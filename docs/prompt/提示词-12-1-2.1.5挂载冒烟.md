## 七、设计约束（陷阱）

1. **不加提示**：Lead 规则要求用 `Agent` 工具、`TeamCreate`、`present_files`，dsh 上没有。**不要**在规则、persona 或工具描述里写「请改用 xxx」；让它按原样跑，记录它实际怎么做。这正是本步要摸清的。
2. **隔离 HOME 的副作用**：dsh 的凭据来自 `DSH_HOME/.credentials.yaml`，不依赖 HOME；但其他依赖 HOME 的东西可能受影响（例如 git 全局配置）。冒烟时先确认隔离 HOME 下 dsh 能正常调到模型；不行就记 SETUP_BLOCKED 并停下，不要改回真实 HOME。
3. **守卫误拦**：如果正常业务操作被守卫拦了（例如技能目录里普通文件名恰好命中），如实记录，不改清单重跑。
4. **工具名**：连字符不被接受时才改下划线；改了要列出映射表。
5. **会话读法**：2.1.5 成员会话可能很长，用脚本解压汇总（05 §2.5），不要把整段会话读进上下文。
6. 不碰凭据内容：任何输出都不能出现密钥；`来源.md` 里的 sha256 对照表不包含被排除的 connection.dat。
