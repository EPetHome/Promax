# 10c-3 续接｜Loop 执行提示词

本次为 NJ 第 1/2 轮的裁决后续接，开发 GPT-6.1 Sol / max；模型与工具由 task.json 固定。用户启动 Loop 后才开始执行。此提示与任务 10 顶部续接规则配套，不直接执行旧调度脚本。

## 读取与本轮范围

以本单元 `LOOP_CONTEXT` 中的角色、候选路径、标准、只读/可写范围及预算为准。读 `reference/任务规则.md`、`reference/原因分析.md`，按需要查 `reference/既有复核.md` 的 R10-7。后两者只提供故障证据，不改变授权。

`spec`：只读审查规格完整性、实际运行包接口、验证接法和次数；逐条报告可行性或具体冲突，不改产品，不调用真实场景。不得把待开发项本身写成规格无法执行。

`repair`：唯一能改产品的单元，最多两个候选（首次加一次返修）。修真实事件计数、JSON 单独修复额度、同组全部保存才结束周期、如实交付及 Judge 写入前限制。逐一追踪预检、提交、保存的共用逻辑，复用现有流水；保留旧字段和失败证据。写手自查不得污染正式检查。旧测试原文在 `reference/旧测试/`；必要改变必须注明对应 D26 条款，不为通过删断言。

Judge 扩展固定交付在 `promax-project/team/extensions/judge-write-guard/`，profile 只允许修改 headless 的 cordis.patch.yml；优先使用已安装包中的 tools/pre-execute 或 monotonic execution guard 等真实接口，参考已复制的 runtime 类型和实现。挂载身份和允许路径必须由可信宿主绑定，不相信 Judge 自报路径。若现有接口不足且必须改核心或升级，明确阻塞并停止。

场景接法会把原项目路径映射到隔离候选，并设置 `PROMAX_GUARD_EVIDENCE`。扩展必须在实际挂载成功时向此路径追加一条 JSONL，含 `event: "guard-ready"`、`module_path`（真实加载的扩展模块绝对路径）；允许/拒绝操作也须留出调用身份、目标、决定和原因记录，供原始工具会话交叉核对。这只是证据接口，不能靠伪造日志代替限制。扩展路径不能硬编码成候选目录；可用模块自身位置或运行时上下文。

定向检查放 `verification/test_nj_resume.py`，必须可被标准库 unittest 发现且实际执行。至少覆盖 reference 中列明的九类回归和工具边界正反例；不少于 9 个有真实断言的测试。可在同目录放必要的本地辅助测试，不能改 validation 程序。工具边界测试需走实际挂载调用链并证明越界工具体未执行；单测自己写的字符串判断函数不充分。测试不得联网或调用模型。开发阶段可运行受保护 `validation/offline_gate.py --code <本候选> --workspace <本次工作区新目录>`。

`pilot`：只读核对修复候选和已有离线结果；不要自己启动模型。程序门禁会独立运行 S0 和 C06，随后 Astra 按原始证据审。小试不能作为七场正式成绩。失败时此 Loop 运行停止，不自动回流或重置 repair 额度。

`formal`：只读确认七场标准和候选一致性；不自行跑场景或改代码。程序门禁串行跑七场、控制每场最多一次重跑、保留失败并导出原始会话。你不能根据摘要预写通过。正式运行后只允许 Astra 静态复核，不再自动改代码。

## 交付

按 Loop JSON 协议逐项说明已做、证据和未知。区分“候选代码”“离线检查”“业务场景”“实际装配”，禁止声称原项目已更新。规则矛盾、接口不足、缺关键证据按真实阻塞交付；常规技术问题在剩余额度内修，不回避。
