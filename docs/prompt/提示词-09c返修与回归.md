## 七、设计约束（陷阱）

1. **反引号和中英文标点**：F1—F4 的原文和替换文本里有反引号、中文引号、`——` 与 `—`。用脚本做逐字替换，并断言每处原文**恰好命中 1 次**；命中 0 次或多次就停下报告，不要凭印象手改。
2. **只改指定行**：F3 是在一行很长的英文里替换一段，替换后同一行前后的文字必须和原来逐字节相同。
3. **F6 不改脚本**：`resources/scripts/` 下的脚本不动，也不要去运行这些快速验证命令。
4. **会话目录名以 `--` 开头**：解压用 Python `subprocess.run(['zstd','-dcf','--',path])`。会话在 `promax-project/dsh-home/sessions/--Users-Admin-Desktop-Promax-promax-project-runs-<编号>--/<会话>/session.v4.jsonl.zstd`。Lead 会话 id 以 `session-` 开头；成员会话原文里有「成员 xxx」。
5. **`bg_run` 的外层退出码 0 不代表 dsh 成功**：以 `timing-*.json` 的 `exit_code` 和会话 `turn/end` 为准。
6. **成员乱序**：同一场景里同一角色可能有两个成员会话（Lead 重派）。先后顺序按会话里第一条事件的时间排，不按会话 id 的字典序（R09-2 里 pi 就因此把 C05 两位成员的顺序写反了）。
7. **M6 必须全量**：扫全部会话的全部 `tool/call` 参数，不抽样；相对路径（如 `../../team/`）要按命令的 cwd 解析成绝对路径再判；`/dev/null` 重定向不算越界；bash 里 `cd` 到别处再操作也要识别。
8. **文本匹配会被格式挡住**：Markdown 加粗、中英文引号不同，都会让匹配失败。「没匹配上」要人工确认。
9. **进程检查**：用 `pgrep -f "[.]bin/dsh --profile"`（不加方括号会匹配到检查命令自己），记录返回码。
