## 六、改造规格

按规格逐条实现，重点：

- **发现**：K1 frontmatter（中文名）；K2 重复两条都不进清单、读不出跳过，日志事件与字段按 S1.1 定义，同进程同事件 + 同 name/path 只记一次；K3 每次需要时重扫（只读 frontmatter）。
- **清单**：K4 摘要算法、首行说明原文、每条格式、长描述处理、未变不重发；K5 fork 子会话不发布清单、不提供 `Skill`。
- **调用**：K6 错误原文；K7 有 `wbRuntime` 才签发和改写；K8 fork 任务文本、返回首行逐字 `Skill "<名>" completed (forked execution).`、子会话工具集合与模型；K9 内联返回；K10 并发上限排队、不报「已达上限」、排队毫秒交给 `finishFork`。
- **共通**：1.3 日志固定键与 UTC；`Skill` 允许额外字段并写进日志。

## 七、设计约束（陷阱）

1. **逐字**：返回首行、`Base directory for this skill:`、`ARGUMENTS:` 段、错误原文一个字符都不能差。
2. **fork 的完成由程序宣告**：返回首行由插件拼，不能依赖子会话模型自己说「completed」。
3. **两种装载都要对**：只装 skill（门禁测的）与装上 runtime（批 4 测的）两条路径行为一致，只差签发、改写、台账。
4. **门禁不是规格**：门禁断言看起来与 S1.2 矛盾，先找规格原话；确认矛盾就照规格做，记进结果，不改门禁。
5. **不自造接口**：找不到公开接口做某件事，停下记录，不 monkey-patch dsh 内部。
